# 2026-11-19 WinWidget

## 修复「玩出花 Bloom」全屏特效盖住桌面 / 挡住操作

用户诉求：特效全屏画在桌面，但不影响桌面图标显示与点击、不影响其他应用操作。
组件已有 d4e2a7b 的"桌面层+真透明"机制，参数名/颜色解析/canvas 清屏都正确，失败在两个机制性缺陷。

### 根因（已逐一验证）
1. **鼠标穿透只做一次，时机过早**：`main.js openOverlay` 在 `win.create` 返回瞬间就调
   `setIgnoreMouseEvents`，但 WebView2 的子 HWND 是异步建的；`set_click_through` 的
   `EnumChildWindows` 那一刻枚举不到迟到的子窗口，`mark_custom_loaded`(ready) 也不重放。
   → 点击停在特效子窗口上，穿不到桌面图标/其他应用。
2. **retroGrid 不透明铺底**：`effects/retroGrid.js` 用不透明 hex 渐变 fillRect 铺满天空
   (0..horizon)+地面(horizon..h)，整屏 alpha=1，选这支特效就把桌面完全盖住。
   其他铺底特效（fireVortex/glitchVision 低 alpha 逐帧、deepSea/sunsetSea 离屏 rgba）不致命。

### 修复（本地提交，未 push）
- `src/runtime/app.rs::mark_custom_loaded`：ready 时对 `ignore_mouse==true` 的窗口重放
  `set_click_through`（子窗口此时已建好）；用局部变量收 hwnd 避免借用冲突，保留"只通知一次"语义。
- `src/runtime/window_category.rs::build_custom`：建窗时若 `ignoreMouseEvents:true` 立即应用穿透，
  与 ready 重放形成双保险；`ignore_mouse` 提取为局部变量。
- `assets/widgets/bloom/main.js`：openOverlay options 里加 `ignoreMouseEvents:true`。
- `assets/widgets/bloom/effects/retroGrid.js`：天空/地面不透明 hex 改带 alpha 的 rgba
  (0.18~0.28)，桌面图标透得出，保留霓虹紫层次。

### 未做（高风险/非核心，判断收益不足）
- **桌面层 z 序**：`place_above_desktop` 用 GWLP_HWNDPARENT=Progman + SetWindowPos，窗口是
  top-level owned，视觉上靠"真透明"让图标透出。探索代理建议改 WorkerW/SHELLDLL_DefView
  子窗口方案，但子窗口会失去 DWM per-pixel alpha（特效变白底），且该函数被所有桌面层卡片
  共用（window.rs + window_category.rs），刚经 d4e2a7b 验证——风险远大于收益，不动。
- **焦点抢回** 8×250ms=2s 轮询偏短、overlay.js 的 Escape 监听是死代码（窗口 no-activate+
  穿透收不到键盘）——非用户核心痛点，不扩大改动面。

### 验证
fmt / clippy -D warnings(0 error) / 58 tests / 架构护栏 60 无漂移 / API 58 / 两个 JS node --check 全绿。

## 第二轮：白屏真正根因（用户截图反馈仍纯白全屏）

第一轮只修 retroGrid 铺色 + 穿透时机，没触及透明机制本身。用户截图：纯白底 + 淡蓝螺旋粒子，
桌面图标在白底下隐约可见 → 窗口被蒙了一层半透明白色，来自 DWM 层，不是 canvas。

### 根因（权威资料坐实）
`set_see_through()`（d4e2a7b 引入，仅 bloom 的 seeThrough:true 用）设
`ACCENT_ENABLE_TRANSPARENTGRADIENT(2)` + `gradient_color=0`，注释臆断"zero alpha paints nothing"。
实测资料明确：该 state 会"完全用系统主题色/强调色绘制窗口，不管后面是什么，没有透明度"，
浅色主题下即白色 —— 与截图像完全吻合。真正的透明配方是 tao 空 blur region + extend_frame +
per_pixel_alpha + WebView2 (0,0,0,0)，accent 根本不该参与。

### 修复（本地提交）
- `src/platform/win32.rs::set_see_through`：`on=false` 且 accent_flags=0 → 等价于 ACCENT_DISABLED，
  不再画任何 DWM backdrop；更新注释记录真实原因。
- `src/runtime/window_category.rs::build_custom`：把 seeThrough 调用从 frame 操作之前移到
  extend_frame/per_pixel_alpha 之后（最后一次 recomposite 之后再关 backdrop）。

### 有意回退、未采纳的改动
探索建议加 `WS_EX_LAYERED` 改善跨进程穿透（tao set_ignore_cursor_events 就是这对），但
d4e2a7b 当初正是去掉它才消白屏；无法实测 GUI，避免白屏复辟风险，穿透保持 4521ff1 现状
（set_click_through 顶层+子窗口 WS_EX_TRANSPARENT + ready 重放）。若白屏修复后仍不穿透，
下一步再单独处理（可能需 HTTRANSPARENT subclass 或 tao set_ignore_cursor_events）。

### 验证
fmt / clippy 0 error / 58 tests / 护栏 60 无漂移 / API check 全绿。无法在此环境实测 GUI，
需用户 cargo build 后实机确认白屏是否消失。

### 权威资料
ACCENT_ENABLE_TRANSPARENTGRADIENT = 系统主题色实心底、无透明度（dotnet-campus / walterlv 博客，
StackOverflow "glass blend colour"）；gradient_color=0 不是透明，反渲染成黑/主题色。

## 第三轮：bloom 白屏彻底根治（找到真正架构根因，实测验证）
前两轮都在猜 DWM/accent 谁画了白色，方向错了。用户第三次反馈"就是打开了一个窗口把桌面
全部覆盖了，其他都操作不了"。这次改用 ctypes 直接探测真实桌面窗口树，拿到确凿证据。

### 运行时证据（本机 Win11，python ctypes 实测，非推测）
- Progman `GWL_EXSTYLE = 0x00200080` → **WS_EX_NOREDIRECTIONBITMAP 置位 = 24H2+ raised desktop**。
- 桌面图标 `SHELLDLL_DefView` + `SysListView32` 是 **Progman 的直接子窗口**（可见）。
- 19 个 WorkerW 全部不可见、都不含 DefView → **经典 0x052C 找 WorkerW 算法本机完全无效**。
- 正在运行的 winwidget.exe(PID 25276) 窗口：卡片 parent=Progman、style 0x96000000（top-level popup）。

### 真正根因
`place_above_desktop` 把窗口设成 Progman 的 **owner（仍是 top-level WS_POPUP）**。按 Win32 z 序
规则，owned top-level 窗口**永远绘制在 owner 及其所有子窗口之上** —— 桌面图标是 Progman 的子
窗口，所以特效必然盖住图标。透明度/鼠标穿透/accent 全都补不了 z 序，前两轮必然失败。
另外 `GW_HWNDPREV` 返回 0 时兜底 `HWND_TOP` 会直接置顶，正是"其他都操作不了"。

### 修复（新增 layer:"wallpaper"，不动卡片路径）
- `win32.rs` 加 FindWindowExW / SendMessageTimeoutW + 常量；新增 `wallpaper_host()`（raised 检测
  WS_EX_NOREDIRECTIONBITMAP，raised→host=Progman+DefView；classic→0x052C 找 WorkerW）和
  `place_on_wallpaper(hwnd, screen)`：改 WS_CHILD、清 owner、SetParent(host)、父客户区坐标定位、
  **SetWindowPos(after=DefView) 压到图标之下**、set_no_activate + set_click_through。
- `window_category.rs::build_custom`：`layer=="wallpaper"` 时跳过整套透明 DWM 设置、跳过
  place_above_desktop/topmost，WebView 建好后才挂载；**挂载失败返回 Err**（不留孤立顶层窗口）。
  CustomWin 加 `wallpaper` 字段；show/hide 走 w::show_no_activate/w::hide；invoke 集中拦截
  move/resize/raise/fullscreen 等会触发 tao window-flags diff 重写 style 破坏挂载的方法。
  **关键**：tao 的 set_visible/set_ignore_cursor_events 走 flags diff 会把 GWL_STYLE 写回 WS_POPUP，
  挂载后必须全部避开（win32.rs set_topmost 注释早记录过同类坑）。
- `bloom/main.js`：layer desktop→wallpaper、去掉 transparent/seeThrough、backgroundColor 改不透明
  深色 #0a0e1a；`overlay.html` body/canvas 用 !important 钉死不透明深色底 + 隐藏 SDK 卡片 UI
  （SDK 会给 custom window 注入 base.css/主题 CSS/.fw-resize 等）。壁纸层不透明 = 它就是新壁纸。

### 实测验证（三次 ctypes，决定性）
1. `SetWindowPos(after=DefView)` 方向实测：z 序变成 `DefView → probe`（图标在上、特效在下）。
2. 完整挂载模拟：窗口变 Progman 的 WS_CHILD，ShowWindow 后仍保持，z 序 `DefView(可见) → EFFECT`。
3. 新增单测 `wallpaper_host_finds_the_icon_layer` 在真实 Windows 跑通（68 tests）。
证据链远强于前两轮的纯推测。
