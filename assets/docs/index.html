WinWidget 组件开发指南

一个组件就是一个文件夹：一个 widget.json 说明文件，加上普通的 HTML、CSS 和 JavaScript。会写网页，就会写组件。

十分钟写第一个组件

我们来做一个“每日一句”：每天显示一句话，按一下换下一句，句子可以在控制中心改。

1. 建立组件（1 分钟）

  • 左键点托盘图标，打开控制中心。
  • 到控制中心“添加组件”页，按右上角的 新建组件…（窗口窄时只显示“＋”图标）。也可以右键系统托盘图标 →“添加组件”→“新建组件…”。
  • 名称输入 每日一句，按 建立。

WinWidget 会：

  • 在组件目录建立一个文件夹（例如 %AppData%\WinWidget\widgets\my-widget），里面是一个能用的模板；
  • 把它放到桌面；
  • 打开 开发者模式：之后改了文件夹里的文件，一保存，桌面上的组件就会自动重新加载；
  • 用资源管理器打开这个文件夹。

用你习惯的编辑器打开这个文件夹。推荐 VS Code：文件夹里的 widget.d.ts 会让它在你打 widget. 时列出所有可用的功能和说明。

2. 加一个设置项（1 分钟）

打开 widget.json，把 settings 整段换成：

"settings": [
  { "key": "quotes", "type": "textarea", "label": "句子（一行一句）",
    "default": "慢慢来，比较快。\n今天也要好好吃饭。\n先完成，再完美。" }
]

保存。打开控制中心 →“我的组件”→ 选“每日一句”→“内容”，会看到一个多行文字框，里面是这三句话。这个表单是 WinWidget 照 settings 自动生成的。

3. 写画面（3 分钟）

把 index.html 换成：

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="w-label" id="day"></div>
  <p class="quote" id="quote"></p>
  <button class="w-btn" id="next">换一句</button>
  <script src="main.js"></script>
</body>
</html>

把 style.css 换成：

body {
  display: flex;
  flex-direction: column;
  gap: 8px;
}

.quote {
  flex: 1;
  margin: 0;
  font-size: 1.3rem;
  line-height: 1.5;
}

#next {
  align-self: flex-end;
}

<body> 就是那张卡片。w-label、w-btn 是 WinWidget 自带的样式，背景、圆角、字体和颜色由主题提供，你不用写。

4. 写逻辑（3 分钟）

把 main.js 换成：

const $ = (id) => document.getElementById(id);
let quotes = [];
let index = 0;

function show() {
  const quote = quotes.length ? quotes[index % quotes.length] : "到控制中心加几句话吧";
  $("quote").textContent = quote;
  $("day").textContent = new Date().toLocaleDateString(widget.locale, {
    month: "long", day: "numeric", weekday: "long",
  });
}

// 读设置：一行一句
function load(settings) {
  quotes = settings.quotes.split("\n").map((s) => s.trim()).filter(Boolean);
  show();
}

// 每天自动换一句；按过“换一句”的话，记住今天换到哪一句
const today = new Date().toDateString();
widget.storage.get("pick").then((pick) => {
  const dayNumber = Math.floor(Date.now() / 86400000);
  index = pick && pick.day === today ? pick.index : dayNumber;
  load(widget.settings.get());
});

// 用户在控制中心改了句子，马上更新
widget.settings.onChange(load);

$("next").addEventListener("click", () => {
  index++;
  widget.storage.set("pick", { day: today, index });
  show();
});

保存，桌面上的组件马上变成新的样子。试试：

  • 按“换一句”；
  • 在控制中心改句子，桌面上即时更新；
  • 到“主题”换一套主题，组件的字体和颜色会跟着变；
  • 重新启动 WinWidget，今天换到的那一句还在（widget.storage 会一直保存）。

5. 出错了怎么办（1 分钟）

开发者模式下，脚本出错时卡片底部会出现一条红色提示，写着错误和位置（例如 main.js:12）。点一下它就会打开开发者工具；也可以在组件上按 F12。改好保存，提示就会消失。

6. 分享出去（1 分钟）

控制中心 →“添加组件”→ 你的组件卡片 →“导出 .fwz”。别人双击这个 .fwz 文件就能安装（也可以拖到控制中心窗口上）。

想让所有人都能在控制中心的“线上”里找到它，可以投稿到组件市场：把组件文件夹放进 GitHub 上 fullwidget-market 保存库的 widgets/你的账号.组件名/，开一个 pull request。自动检查通过、维护者看过后就会上架，详细步骤见那里的 CONTRIBUTING.md。

文件夹里有什么

文件用途
widget.json说明文件：名称、尺寸、权限、设置项。必须有。
index.html组件的页面（可以在 widget.json 的 entry 改成别的档名）。
style.css、main.js样式和逻辑。档名随意，在 HTML 里用相对路径引用即可。
icon.svg在组件库、托盘菜单和控制中心显示的图标（建议 24×24 的 SVG）。
widget.d.ts、jsconfig.json只给编辑器用，让它提示 widget. 的写法。

组件目录：%AppData%\WinWidget\widgets\。在控制中心“设置”→“组件目录”可以直接打开。把一个组件文件夹放进去，它就会出现在“添加组件”里（开发者模式下自动出现，否则按“重新扫描”）。

文件请存成 UTF-8。

widget.json

可以写 // 注解，最后一项后面多一个逗号也没关系。

{
  "id": "me.daily-quote",
  "name": { "zh-TW": "每日一句", "zh-CN": "每日一句", "en": "Daily Quote" },
  "description": "每天一句话",
  "version": "1.0.0",
  "author": "你的名字",
  "entry": "index.html",
  "icon": "icon.svg",
  "category": "info",
  "size": {
    "width": 280, "height": 160,
    "minWidth": 200, "minHeight": 120, "maxWidth": 600, "maxHeight": 400,
    "resizable": true
  },
  "layer": "desktop",
  "permissions": [],
  "settings": []
}
字段必填说明
id是唯一标识。小写英文、数字和 . _ -，2–64 个字元，例如 me.daily-quote。之后不要改：保存的数据和更新都靠它。winwidget. 开头的留给内建组件。
name建议显示的名称。可以是文字，也可以按语言给：{ "zh-TW": "…", "en": "…" }。
description一句话介绍，显示在组件库。同样可以按语言给。
version建议版本号，例如 1.2.0。安装 .fwz 时用它判断是更新、重新安装还是旧版本。
author作者。
entry页面档，默认 index.html。
icon图标档。没有的话显示名称的第一个字。
category在组件库里放在哪一类：time（时间）、weather（天气）、system（系统）、productivity（效率）、info（信息）、media（媒体与装饰）。不写或写别的，放在“其他”。
preview组件库卡片上的预览图，例如 "preview.png"。可以按主题和语言各放一张："preview/{theme}.{lang}.webp"，{theme} 换成主题 id（instrument、type、paper），{lang} 换成 zh-TW、zh-CN 或 en；缺的那张会用同主题的其他语言，或其他主题代替。图片建议用透明背景的 PNG 或 WebP，宽 300 像素左右。没有的话卡片显示图标。
size卡片尺寸（不含阴影），单位是像素。width/height 是第一次放上桌面的大小；min*/max* 限制用户拖动缩放的范围；resizable: false 不让缩放；grow（0–1）决定用户把卡片拉得比默认大时，内容要不要跟着放大，见放大时内容跟着变大。
layer第一次放上桌面时的层级：desktop（默认，在所有窗口下面，Win+D 也看得到）、normal、top（置顶）。用户之后可以改。
permissions要用到的权限，见权限。
settings设置项。控制中心会照这里自动生成表单。

settings：设置项

每一项：

{
  "key": "city",
  "type": "text",
  "label": "城市",
  "description": "留空就自动定位",
  "default": ""
}
字段说明
key程序里用的名字：widget.settings.get("city")。
type见下表。
label表单上的名称。可以按语言给。
description名称下面的一行小字说明。
default默认值。任何类型都可以按语言给，例如 { "zh-TW": "google", "zh-CN": "baidu", "en": "google" }。
placeholder输入框里的提示文字。
min max stepnumber 和 slider 用。
optionsselect 用：[{ "value": "c", "label": "摄氏" }, { "value": "f", "label": "华氏" }]。
type表单值
toggle开关true / false
text单行文字字串
textarea多行文字字串（换行是 \n）
number数字框数字
slider滑块数字
select下拉菜单（三个以内的短选项会显示成分段按钮）选项的 value
color颜色"#rrggbb"
font字体（可从系统字体中选）字体名称；用户清空时是 null（通常就用主题的字体）
date日期"2026-12-31"
folder文件夹（显示路径和“选择…”按钮）完整路径；默认值可以写环境变数，例如 "%USERPROFILE%\\Pictures"。见 [widget.files](#读取用户选的文件夹widgetfiles)

JavaScript API

WinWidget 会在你的脚本执行前准备好全局的 widget，不用 import。完整的型别和说明在 widget.d.ts。

需要等待的功能（读写数据、连网等）都回传 Promise，可以用 await。

基本数据

widget.id          // "me.daily-quote"
widget.instanceId  // 桌面上这一个的标识（同一个组件可以放几个）
widget.locale      // 用户的语言，例如 "zh-TW"，格式化日期和数字用
widget.theme       // 目前的主题："instrument"、"type"、"paper"
widget.developer   // 是否在开发者模式
widget.permissions // 现在能用的权限

// 按用户的语言挑文字
widget.t({ "zh-TW": "早安", "zh-CN": "早安", en: "Good morning" })

设置：widget.settings

// 读设置：同步的，不用 await
const all = widget.settings.get();         // { quotes: "…", … }
const one = widget.settings.get("quotes");

// 用户在控制中心改了设置
widget.settings.onChange((all) => { /* … */ });

// 程序也可以改，控制中心会同步显示
await widget.settings.set("quotes", "…");

保存数据：widget.storage

保存的东西重开电脑也在；用户移除这个组件时一起删除。桌面上每一个组件各有自己的一份。上限每个 2 MB。

// 可以存任何 JSON 数据
await widget.storage.set("todo", [{ text: "买牛奶", done: false }]);

// 没存过的是 null
const todo = (await widget.storage.get("todo")) || [];

await widget.storage.remove("todo");
const keys = await widget.storage.keys();

系统信息：widget.system（需要 system 权限）

const stop = widget.system.subscribe(["cpu", "memory"], (d) => {
  cpu.textContent = Math.round(d.cpu.usage) + "%";
  mem.textContent = Math.round(d.memory.usage) + "%";
}, { interval: 2000 });  // 每 2 秒一次，默认 1 秒；第一笔会马上到

stop(); // 不需要时停止
主题内容
cpuusage（%）、cores
memoryusage（%）、total、used、available（字节）
networkdown、up（每秒字节）、totalDown、totalUp
disk每个磁盘一项（含随身碟）：name（"C:"）、label、type（fixed / removable）、total、free、usage（%）
batterypresent、percent、charging、pluggedIn、secondsLeft、saver（省电模式）

多个组件订阅同一个数据时，WinWidget 只取样一次，不会多耗资源。

不常变的数据用一次性的呼叫：

const pc = await widget.system.info();
// pc.os.name "Windows 11 Pro"、pc.os.version "25H2"、pc.cpu.name、pc.memory.installed（字节）、
// pc.gpus（显卡名称）、pc.computer（电脑名称）、pc.uptime（已开机的毫秒数）

const net = await widget.system.adapters();
// net.online；net.adapters[0] 是连上网络的那个：name "Wi-Fi"、type "wifi"、ipv4、gateways、dns

const r = await widget.system.ping("1.1.1.1");   // { ok, ms, status }；每个组件每秒最多一次

音量：widget.audio（需要 audio 权限）

const stop = widget.audio.onChange((a) => {
  // a.volume 0–100、a.muted、a.device（"喇叭 (Realtek Audio)"）
  // 按键盘的音量键、工作列调音量、换成耳机时都会马上通知
});
await widget.audio.set({ volume: 40 });
await widget.audio.set({ muted: true });

正在播放：widget.media（需要 media 权限）

读取 Windows 媒体控制里正在播放的内容（Spotify、浏览器、媒体播放器……，和音量面板上看到的一样），并控制它：

widget.media.onChange((m) => {
  if (!m.available) return;          // 没有程序在播放
  // m.title、m.artist、m.album、m.app.name（"Spotify"）、m.app.icon
  // m.playing、m.position、m.duration（毫秒）、m.cover（封面图片的网址，可直接放进 <img>）
  // m.can.next、m.can.previous、m.can.seek：那个程序现在接受哪些按钮
});
const now = widget.media.position(m);   // 现在播到哪里（播放中会自己往前走）
await widget.media.toggle();            // 播放 / 暂停；也有 play()、pause()、next()、previous()
await widget.media.seek(60000);         // 跳到 1:00
// 目前这首歌的时间轴歌词，在网易云音乐、QQ 音乐、酷狗上查找
const { title, lyrics } = await widget.media.lyrics();
if (lyrics.found) lyrics.lines;         // [{ t: 毫秒, text, tr?: 翻译 }]，按时间排好

Windows 有变化时会马上通知（换歌、暂停、换了一个程序在播放），不用自己轮询。

读取用户选的文件夹：widget.files

在设置项里放一个 folder 类型的设置，用户选了文件夹，组件就能读取里面的图片。选文件夹本身就是允许，不用在 permissions 声明：

{ "key": "folder", "type": "folder", "label": "照片文件夹", "default": "%USERPROFILE%\\Pictures" }
const { files } = await widget.files.list("folder", { recursive: true });
// files: [{ path: "2025/海边.jpg", name: "海边", size, modified, url }]

const { taken } = await widget.files.info("folder", files[0]);  // 拍摄时间（相机记录的），没有时是 null
await widget.files.pick("folder");      // 在组件里直接打开选文件夹的窗口，选好后存进设置
  • 只能读那个文件夹（和里面的子文件夹）里的图片：jpg、png、gif、webp、bmp、avif、heic、tif，最多 5000 张。
  • 别人写的组件，default 里写的文件夹不算数，要等用户自己选过才能读。内建组件和自己写的组件可以用默认值。
  • 文件夹的设置值里可以写环境变数，例如 %USERPROFILE%。

生命周期：ready → show → hide → unload

一张卡片从被加载到被移除，外壳会按固定顺序发事件。全部用 widget.on(名称, 回呼) 订阅，回传值是退订函式。

事件什么时候来内容
ready页面起来了（DOMContentLoaded 之后再过一个工作，所以你写在 DOMContentLoaded 里的订阅一定听得到）{ visible }
show卡片出现在屏幕上。开机那次也算一次，带 initial: true{ from, visible: true, initial }
hide卡片离开屏幕：隐藏全部、托盘单张隐藏、全屏幕让位、window.hide(){ from, visible: false, initial: false }
resize卡片尺寸变了（拖边、拖角、控制中心改大小）。连续变化会去抖 80ms，只回报停下来的那一个{ width, height }，CSS 像素
unload卡片要被移除、或整个程序要结束{ kill: true }

from 说明这次显示/隐藏是谁造成的：

from谁
startup开机跟着外壳一起显示
tray托盘菜单（显示/隐藏全部、单张显示/隐藏）
control控制中心（“定位”、显示全部开关）
hotkey全域快捷键叫出来
fullscreen有别的全屏幕程序，这张卡片让开或回来
api卡片自己呼叫 widget.window.show() / hide()

顺序保证

  • ready 一定比第一个 show 早。所以“启动时要做一次”的初始化写在 ready 里，不会被 show 打乱。
  • 已经在屏幕上的卡片（开机默认）会在 ready 后立刻收到 show{ initial: true }；启动时被隐藏的（例如开了“隐藏全部”）不会收到，等真的显示才有。
  • show / hide 是成对的，而且同一个状态不会重复发：hide 之后再 hide 没有第二次；show 之后再 show 也没有。用 widget.visible 随时查目前状态。
  • hide 会在卡片仍活着的时候到，unload 是“这次真的要走了”。只做一次的事（保存、关定时器）放 unload，暂停动画放 hide。
// 边跑边省电：看不见就停，回来再算一次
let timer = 0;
function start() {
  if (timer || !widget.visible) return;
  timer = setInterval(tick, 1000);
  tick();
}
function stop() {
  clearInterval(timer);
  timer = 0;
}

widget.on("ready", () => start());
widget.on("show", ({ from, initial }) => {
  widget.log("shown", from, initial);   // from 见上表
  start();
});
widget.on("hide", () => stop());
widget.on("unload", ({ kill }) => {
  stop();
  if (kill) widget.storage.set("lastSeen", Date.now());
});

// 尺寸变了再排版（不用听 window 的 resize，那是整窗，带 DPI 换算）
widget.on("resize", ({ width, height }) => {
  document.body.dataset.compact = width < 260 ? "1" : "";
});

widget.visible 是随时可读的目前状态，SDK 会跟着 show / hide 更新。卡片刻意不去抢键盘焦点，所以没有 focus / blur 事件；要用键盘输入的组件，自己在卡片里放输入框，用户点它才会拿到键盘。

和 uTools 那七个事件的对照

uTools 的事件是“外挂程序 vs 主窗口”的模型；WinWidget 的卡片本身就是一个独立窗口，所以只能对到形状相同的那几个：

uToolsWinWidget差在哪
onPluginReady(cb)widget.on("ready", cb)一样只在加载后一次。uTools 会等 cb 的 Promise；这里不会等，要“等完再进”用 utools.onPluginReady
onPluginEnter(cb)widget.on("show", cb)参数形状见下；每次显示都触发，不只是第一次
onPluginOut(cb)widget.on("hide", cb) + widget.on("unload", cb)hide 对应 isKill: false，unload 对应 isKill: true
onPluginDetach(cb)无卡片本来就是独立窗口，没有“分离”这一步；utools.onPluginDetach 会登记但不触发
onScheduleTrigger(cb)utools.onScheduleTrigger(cb)一样。自写的 cron 到点会真的调 cb，{ code, label, at }
onMainPush(cb, onSelect?)utools.onMainPush(cb)有，语意是“带着 payload 被唤起”：redirect(label, payload) 命中本组件的动态功能后，向被唤起的那张卡片推 mainPush，cb(action, payload) 收 { code, type, payload, from }。onSelect 不实作（没有结果列表可选）
onDbPull(cb)utools.onDbPull(cb)有，但是降级：没有云端，只是同一个组件的其他卡片改了文档时，向本组件的每张卡片广播 { direction: "pull", docs: [...] }

utools.onPluginEnter 的参数按 uTools 的 PluginEnterAction 给：{ code, type: "text", payload: "", from }，from 是 uTools 的词（main / panel / hotkey / redirect），由上表的 from 映射过来：startup、fullscreen → main，tray → panel，hotkey → hotkey，control、api → redirect。option 只有在“从推送结果进来”时才有，这里不会有。

开自己的窗口：createBrowserWindow

卡片本身是 uTools 说的 main window（utools.getWindowType() → "main"）。要开设置面板、预览窗、全屏幕展示这种第二个窗口，用 utools.createBrowserWindow(url, options, callback)：定义照 uTools / Electron 的 BrowserWindow，同一份页面在这种窗口里 getWindowType() → "custom"。

const win = utools.createBrowserWindow(
  "panel.html?mode=edit",              // 组件文件夹里的 HTML，可以带 query
  {
    width: 520, height: 380,           // 页面区域，不含标题列
    title: "设置",
    show: false,                       // 先别露面，等 callback 再显示，避免白屏
    resizable: true,
    alwaysOnTop: true,
    backgroundColor: "#0f1a24",
  },
  (w) => {
    w.show();                                    // 页面 ready 了才显示
    w.webContents.send("hello", "从卡片来");      // 卡片 → 窗口
  }
);
win.on("closed", () => widget.log("窗口被关掉"));

这个窗口是什么

  • 它是同一个组件的页面：同一个 origin（<组件 id>.widgets.localhost）、同一份 localStorage、同一套主题和 SDK。所以 widget.storage、widget.settings、utools.dbStorage 两边看到的是同一份数据。
  • 页面里 widget.windowType === "custom"、widget.windowId 是这个窗口的号码；utools.getWindowType() 回 "custom"。卡片那边是 "main"、windowId 是 0。
  • 号码从 1 开始，一个组件同时最多 24 个窗口。
  • 卡片被移除、或整个程序结束时，它开的窗口一起关掉（先关子窗口，再关父窗口）。

外观：跟着主题走

WinWidget 有几套主题，用户也能在控制中心调整背景、文字颜色、强调色、字体、字号、圆角、内边距和透明度。只要你的组件用下面这些变数和样式，这一切都会自动生效。

版面

  • <body> 就是卡片：背景、圆角、边框、内边距都已经设好。内容直接放进 <body>。
  • <html> 是透明的窗口，四周留了给阴影的空白，不要给它加背景。
  • 字号用 rem：用户调“字号”时，1rem 会跟着变（默认 14px）。
  • 卡片可能被缩放。用 flex/grid 排版；要按大小调整，可以在 body 上设 container-type: size，再用 @container (max-height: 100px) { … }。注意 @container 只能改 body 里面的元素，改不了 body 本身。

放大时内容跟着变大

在 widget.json 的 size 加上 "grow": 1，用户把卡片拉得比默认大时，整张卡片的内容会一起放大，字、图标、间距都按比例变大，不会只是多出空白：

"size": { "width": 260, "height": 150, "minWidth": 180, "minHeight": 110, "grow": 1 }
  • 放大的倍数是“宽放大几倍”和“高放大几倍”中较小的那个，最多 3 倍。例如拉到两倍宽、1.3 倍高，内容放大 1.3 倍，多出来的宽度交给你的排版。
  • 比默认小时不会缩小，小尺寸要靠你自己的排版（上面的 @container）。
  • grow 可以是 0 到 1 之间：列表类的组件写 0.5，拉大时字变大一点，同时多显示几项。
  • 不写或写 0：和以前一样，只是多出空间。
  • 卡片的圆角、边框和阴影不会跟着放大。目前的倍数在 CSS 变数 --w-size-scale。

省电：每秒更新的东西不要加动画

组件整天开着，每一帧画面都要算。每秒更新一次的数字或进度条，如果加了 0.5 秒的 transition，画面就几乎一直在动，一个组件可以吃掉 20% 的处理器核心；不加的话只要 1%。

  • 每秒或更频繁更新的元素，不要 transition 和 animation。w-bar 默认有 0.5 秒的宽度动画，每秒更新时写 .w-bar > i { transition: none; }。
  • 不要 animation: … infinite；要闪烁提示，给一个次数（例如 8）。
  • 指针、转盘这类要转的东西，放在独立的元素上用 CSS transform 转，不要每秒重画整个 SVG。
  • 每分钟才变的东西，就每分钟才更新（setTimeout 对准下一分钟）。

拖动、菜单和点击

WinWidget 已经帮你处理好：

  • 拖动：在卡片任何地方按住拖动，就能移动组件。按钮、链接、输入框不会触发拖动；其他元素不想被拖动时，加上 data-no-drag。
  • 右键：显示 WinWidget 的组件菜单。某个区域要自己处理右键时，加上 data-no-menu。
  • 缩放：size.resizable 不是 false 时，右下角会有缩放手把。
  • 锁定：用户锁定组件后不能拖动和缩放；你可以用 widget.locked 和 html[data-locked] 知道。

组件默认只能显示自己的内容：不能连网、读不到系统信息、也碰不到你电脑上的文件。要用到这些，在 widget.json 的 permissions 里声明：

谁来允许：

  • 用“新建组件”建立的组件是你自己写的，声明的权限直接生效。
  • 别人的组件，安装时会列出它要的权限，用户按“安装”才算允许。更新后多要了权限，用户要再允许一次，在那之前新权限用不了。
  • 把别人的组件文件夹直接放进组件目录的话，第一次放上桌面时会先请用户允许。

连网的规则： 不只 widget.fetch，页面里直接加载的图片、字体、脚本、fetch() 和 WebSocket 也只能连到允许的网站。差别是：直接 fetch() 要对方网站支持 CORS，widget.fetch 不用。

打包和分享

.fwz 就是把组件文件夹压成 zip、改了副档名。

  • 导出：控制中心“添加组件”→ 你的组件卡片 →“导出 .fwz”。隐藏的文件和文件夹（例如 .git）以及 node_modules 不会被打包。
  • 安装：双击 .fwz 文件、把它拖到控制中心窗口上，或在“添加组件”按“安装 .fwz 文件…”。安装前会显示名称、作者、版本和需要的权限。
  • 更新：改大 version 再导出。id 相同的组件会被替换，桌面上的组件、设置和保存的数据都会保留；旧版本移到资源回收筒。
  • 用框架写：React、Vue、Svelte 都可以，只要输出静态文件。把建置结果（例如 dist/）和 widget.json 放在一起，entry 指向它的 index.html；资源路径要用相对路径（例如 Vite 设 base: "./"）。
  • 大小限制：.fwz 最大 64 MB，解压后最多 256 MB、5000 个文件。

装 uTools 外挂（.upx）

同一个“安装 .fwz / .upx…”按钮（以及拖放到控制中心）也认 uTools 的 .upx。它其实是 gzip 包着“16 字节头 + JSON 目录 + 4 字节对齐 + 文件数据”，WinWidget 会就地拆开，用 plugin.json 生成一份 widget.json：

plugin.json变成
name（一串小写字母数字）id；缺失或不合规时按 pluginName 散列成 uplugin-xxxxxxx
pluginNamename（中文名照原样显示）
main / logoentry / icon
version / author / description同名字段
features / preload记在 widget.json 的 utools 区块里，仅作留痕

权限是从页面程序码里扫出来的（看到 utools.copyText 就给 clipboard，看到 utools.screen.* 就给 screen，依此类推），安装前的确认框会照常列出来让你决定。

一个已知的天花板：uTools 的 preload.js 跑在 Node.js 里，而 WinWidget 的页面跑在 WebView2 里，没有 Node。所以纯网页外挂（HTML + JS + jQuery 之类）能直接跑；依赖 preload 的外挂装得进来、页面也能开，但 preload 提供的能力不可用。日志里会写一条 upx: "…" declares preload.js — Node.js is not available in this host。

.upxs：新版市场安装包读不了，从已安装的外挂转过来

uTools 自 5.0.0 起把市场安装包换成了 .upxs：整包加密、附开发者签名，用来保证“来自可信任开发者、没被改过”。WinWidget 没有这把钥匙，所以拖 .upxs 进来只会得到一句明确的提示，而不是假装解包成功：

没办法安装这个文件
this is a uTools UPXS package (encrypted and signed since uTools 5.0).
WinWidget has no key for it, so the files cannot be read here.

官方 changelog 的原话是“安装包格式升级为 UPXS 格式。这一格式不仅具有加密功能，还包含开发者信息签名”。实测那个 1.6 MB 的文件，除了头 4 个字节（c8 01 00 00）之外整块熵值都是 8.0，找不到 zip／gzip／JSON 的任何痕迹，也不是异或那种能靠频率分析还原的东西。

可行的路子是先在 uTools 里装好，再把装好的外挂搬过来：uTools 解出来的外挂放在 %APPDATA%\uTools\plugins\，是一个个 .asar（Electron 的封存，没有加密）。WinWidget 直接认这种文件：

  • 在 uTools 里正常安装那个外挂；
  • 到 %APPDATA%\uTools\plugins\ 找到对应的 <一串 hash>.asar（不确定是哪个就用“添加组件”页的导入按钮逐个试，安装确认框会显示外挂名）；
  • 在控制中心“添加组件”→“安装 .fwz / .upx…”选中它，或者直接把 .asar 拖到控制中心。

.asar 的头是 [u32 4][u32 pickle][…][u32 jsonLen]，数据区从 8 + pickle 开始，目录项是 {size, offset:"…", unpacked?, link?}——和 .upx 只差一个头，所以两者共用同一套“拆包 → 用 plugin.json 合成 widget.json”的流程。带 unpacked 标记的文件（原生模组之类）从旁边的 <名字>.asar.unpacked\ 目录读。

顺带说明：utools.getAppVersion() 报的是相容级别（目前 7.6.0），不是 WinWidget 自己的版本号。外挂普遍写 parseFloat(utools.getAppVersion()) < 7 判断底座够不够新，报 1.0.0 会让它们直接画一张“uTools 版本太低”的页面挡住一切。

带 preload.js 的外挂：window.services 接桥

uTools 的 preload.js 跑在 Electron 的 preload 里，require("fs")、require("electron") 都有；WinWidget 的页面在 WebView2 里，没有 Node。所以带 preload 的外挂以前会白屏——页面第一次碰 window.services.xxx() 就抛 Cannot read properties of undefined，整页 React 挂不上去。

现在宿主会往每个组件页注入 services.js（在 utools.js 之后），用同名的方法把 window.services 接成宿主桥：

preload 里的方法现在由谁答
readAllRecords / removeRecords / clearAllRecords宿主的剪贴板历史：clipboard.history，存在 data\clipboard-history.json（最近 300 条，文字和文件）
listenAppendRecord(cb)宿主每 700ms 扫一次剪贴板，有新内容就推给页面
filesExists(paths)clipboard.filesExist
executeCopy / executePaste转给 utools.copyText / copyFile / hideMainWindowPasteText / hideMainWindowPasteFile
dragToFiles、pinScreen、mcpPinData 等目前只是 no-op，会在控制台留一行“not bridged”

window.services 只有在页面自己没有时才会被装上；页面里已经有自己的桥就不动它。

实测（uTools 的“剪贴板”外挂，69699f4f…asar）：卡片开出来是正常的列表，复制任何东西都会立刻出现在最上面，文件记录显示“1 个文件”，点条目复制／贴上都可用。还差的部分写在下面。

两点值得记住：

  • 历史只在宿主执行期间记录。想抓更早的内容，得先有页面在跑（第一次 clipboard.history 会启动监听）。图片暂时不收，所以“图像”那一栏是空的。
  • 装包时的确认框就是授权。以前导入完成只写 permissions，用户还得自己到控制中心点“允许”；现在安装会把确认框里列出的权限写进 grants，并把已经开着的旧页面重载一遍，不会再出现“装好了但每个呼叫都 permission denied”。

还没接的：setSubInput（外挂顶部的搜寻框，uTools 宿主自己画的）、钉图／贴边窗口、把记录拖成文件。

剪贴板历史：一套给 JS 用的完整界面

宿主自己维护一份历史（data\clipboard-history.json，最近 300 条，type 为 text / image / files，最新在前），并把读写都摊成方法。组件里用 widget.clipboard.*，uTools 外挂里用 window.services.*：

方法（widget.clipboard.*）参数作用
history(opts){type, pinned, limit}取记录；type 是 text/image/files/all，pinned 只看收藏
stats()—{all, text, image, files, pinned}，就是四个分类标签上的数字
pin(ids, pinned)记录 id 或 hash 的阵列收藏／取消收藏（pinned 默认 true）
remove(ids)同上删除若干条
clear(opts){keepPinned}清空；keepPinned: true 只留收藏
copy(id)记录 id把这条塞回系统剪贴板
image(id)记录 id图片记录的 PNG data URL
filesExist(paths)路径阵列文件是否还在，回传布林阵列

对应的宿主方法名是 clipboard.history / .stats / .pin / .remove / .clear / clipboard.recopy / clipboard.image / clipboard.filesExist，都要求 clipboard 权限。

“执行贴上”不需要新界面：utools.hideMainWindowPasteText/File/Image 已经是“收起卡片 → 还原前景窗口 → Ctrl+V”，剪贴板里放了什么就贴什么，所以 copy 之后呼叫它就行。

图片记录怎么落地：截图进剪贴板时，宿主把 PNG 存到 data\clipboard\images\<hash>.png，记录里 value 记路径、size 记字节数。uTools 的外挂是按 utools.db.getAttachment("attachment/" + hash) 取图的，所以页面第一次读到这条记录时，services.js 会把字节补传成该组件自己的附件（attachment/<hash>），再把 value 改写成附件 id——列表缩图和收藏流程就都走同一条路。

收藏是两条腿：外挂自己用 collect/<hash> 文件 + utools.db.promises.allDocs("collect/") 记一份，宿主记录上另有 pinned 字段（clipboard.history.pin）。为了让前者能用，utools.js 的 db.allDocs 现在接受前缀字串（以前只认 {idStartsWith}），db.getAttachment 回传的物件也带上了 buffer / byteLength / length（uTools 给的是 Node Buffer，外挂普遍写 new Blob([n.buffer])），db.postAttachment 收 ArrayBuffer / TypedArray。

WinWidget 的能力划分跟 uTools 官方文件一致，页面上用 utools.* 的名字。这一节按分类给最小例子；型别都在 widget.d.ts 的 WinWidget.Utools 里。

和 uTools 插件的关系（相容到哪一步）

uTools 的插件是 Electron 应用：plugin.json + preload.js（在 Node 环境里 require("fs")、装 Sharp / FFmpeg）+ 页面。WinWidget 是 Rust + WebView2，没有 Electron，也没有 Node，所以 uTools 插件不可能原样搬进来。能搬的是“页面 + 页面上呼叫 utools.* 的那部分能力”：每个组件页都会被注入一份 utools 相容层（/__fw/utools.js），把它接到 WinWidget 自己的宿主能力上。

想把一个现成 uTools 插件的画面搬进来

  • 把插件的 index.html、CSS、JS 放进一个组件文件夹；
  • 在 widget.json 里按它用到的能力声明 permissions（showNotification → notify、copyText → clipboard、captureScreen → screen、shellOpenPath → shell.launch、shellOpenExternal → shell.open）；
  • 页面上呼叫的 utools.* 由相容层处理，不必改程序码。

不要指望：preload.js、require(...)、process、fs、child_process。这些在 WinWidget 里不存在，把 preload 原封不动搬进来只会得到一片空白。页面上用到的 ipcRenderer 有相容层（见“开自己的窗口”那一章），它背后是本组件的窗口讯息，不是 Electron 的行程间通讯。

依 uTools 文件的分类逐项对照

WinWidget 现在按 uTools 官方文件的 16 个分类划分能力，每一类在 src/core/ 下有同名文件（window.rs、screen.rs、input.rs…），页面上用到的名字与 uTools 一致。

uTools 的分类WinWidget 里的情况
事件onPluginReady、onPluginEnter、onPluginOut(isKill) 都有，顺序和 uTools 一致（ready 跑完才 enter，隐藏是 false、移除/结束是 true）；onPluginDetach 会登记但不触发（每张卡片本来就是一个窗口）；onScheduleTrigger 现在真的会触发，见“定时任务”；onMainPush 也真的会触发（redirect(label, payload) 带 payload 唤起本组件时），onDbPull 降级为“同组件其他卡片改了文档”的本地广播
窗口createBrowserWindow（自订窗口，见“开自己的窗口”那一章）、hideMainWindow、showMainWindow、outPlugin、getWindowType（"main" / "custom"）、sendToParent、setExpendHeight（只改高度，而且是异步）、findInPage / stopFindInPage（走 window.find）
系统showNotification、shellOpenPath、shellOpenExternal、shellShowItemInFolder、shellTrashItem、shellBeep、getPath、getFileIconAsync、showOpenDialog、showSaveDialog、isDev、isWindows…；getPluginLocalDataPath 回空字串（没有文件系统）
屏幕utools.screen 一族：getAllDisplays / getPrimaryDisplay / getDisplayNearestPoint / getDisplayMatching（回 uTools 的 Display，坐标是 DIP）、screenToDipPoint / dipToScreenPoint / screenToDipRect / dipToScreenRect、capture() / captureDisplay(n)（回 NativeImage）、captureInteractive(timeout?)（拉起 Windows 自带截图浮层，框选完回 NativeImage，取消回 null）、utools.screenColorPick()（光标下的像素）
输入hideMainWindowPasteText / …PasteFile / …PasteImage / …TypeString 都有：先把卡片藏起来，再把键盘交还前一个窗口，然后粘贴或打字。坐标类注入不在这里，见“模拟操作”；input.startDrag 仍未实作
复制copyText、copyImage（data URL / 路径 / NativeImage）、copyFile（一个或多个路径，写 CF_HDROP）、getCopyedFiles()（回 { path, isDirectory, isFile, name }，这里是 Promise）
数据库utools.db 全套：put / get / remove / bulkDocs / allDocs / postAttachment / getAttachment / getAttachmentType / replicateStateFromCloud，存在 data/db/<组件>.json 加附件目录里；dbStorage 仍是本组件的 local storage。没有云端同步，replicateStateFromCloud() 只回 null；put / remove / bulkDocs 之后会向同组件的其他卡片广播 dbPull（就是 onDbPull）
AI 能力预留了分类文件，没有实作：调用会得到 reserved in the ai category 的说明
定时任务requestSchedule(schedule) / getSchedules() / removeSchedule(code) / onScheduleTrigger(fn)：标准 5 位 cron（分 时 日 月 周），也接受一次性时间戳；startTime / endTime 限定生效区间，过 endTime 自动删除。回调抛错或 reject 记成失败，getSchedules() 里能看到 successCount / failureCount / lastStatus

快捷入口utools.redirect(label, payload)（label 可以是 [插件名, 命令]，或单独一个命令名；找不到标签时再用动态功能的 Cmd 匹配这条输入，含 type: "regex"；带 payload 唤起时向目标卡片推 mainPush）、redirectHotKeySetting(cmdLabel, autocopy)（打开控制中心“设置”里的快捷键页）、getCmdHotKey(cmdLabel)（读设置里绑的键）

Sharp 图片处理utools.sharp(input) 链式：resize / rotate / flip / flop / extract / extend / grayscale / negate / blur / sharpen / threshold / gamma / flatten，输出 png / jpeg / webp / tiff，toBuffer / toUint8Array / toFile / metadata。tint / median / composite / trim / normalize 按名抛错
FFmpeg 音视频处理预留了分类文件，没有实作
支付预留了分类文件，没有实作

新增的四个权限见上一节：input（打字注入）、schedule（定时任务）、sharp（图片处理）、ubrowser（页面抓取）。

没有实作或做不全的 API 不会安安静静回 undefined：呼叫时抛一个 code: "utools.unsupported" 的错误，讯息写明是哪一项、为什么。这样比 TypeError: utools.xxx is not a function 好查。语意变了的（同步变异步等）列在 utools.__compat.degraded 里。

新写组件不必绕 uTools

相容层是给“已经存在的网页”用的。新组件直接用 widget.*：型别完整（widget.d.ts）、有权限模型、跟主题走、错误讯息清楚。同一件事两边都有时，widget.* 是主路径，utools.* 是相容路径。

和外壳怎么对接（进阶）

前面几章的写法已经能做出完整的组件。这一章写给想知道“它到底怎么跑起来”的人：页面从哪来、外壳塞了什么进来、有哪些讯息、数据放在哪。看清楚这些，调试和做进阶功能都会快很多。

页面是怎么被加载的

WinWidget 不是用 file:// 打开你的 index.html，而是启动一个只绑定 127.0.0.1 的小型 HTTP 服务，页面由它提供：

http://127.0.0.1:<端口>/__fw/<组件 id>/index.html
  • 端口每次启动都可能不同，所以永远写相对路径（style.css、main.js、img/a.png），不要写死 127.0.0.1:8800。
  • 每一种组件有自己的 origin：<组件id>.widgets.localhost。localStorage、IndexedDB、Cache 都按 origin 隔离，同一种组件的多个实例共用这一份。
  • 页面不能自行跳转到别的网址，也不能开新窗口；要开网页请用 widget.shell.open。
  • 页面里加载的图片、字体、脚本，同样受 permissions 的 network: 限制。

例 1：把一个网络 API 的数字放上桌面

需求：显示某个 GitHub 专案的 star 数，每 30 分钟更新，断网时显示上次的值。

widget.json 重点："permissions": ["network:api.github.com"]。

const $ = (id) => document.getElementById(id);
const KEY = "last";

async function fetchOnce() {
  const r = await widget.fetch("https://api.github.com/repos/Demon1110/WinWidget", {
    headers: { accept: "application/vnd.github+json" },
  });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const repo = await r.json();
  return { stars: repo.stargazers_count, at: Date.now() };
}

async function refresh() {
  try {
    const data = await fetchOnce();
    show(data, false);
    await widget.storage.set(KEY, data);
  } catch (e) {
    // 失败时退回上次的值，并在角落标一下“旧数据”
    const old = await widget.storage.get(KEY);
    if (old) show(old, true);
    else $("stars").textContent = "—";
    widget.log(`stars: ${e.message}`);
  }
}

function show(data, stale) {
  $("stars").textContent = data.stars.toLocaleString(widget.locale);
  $("at").textContent = new Date(data.at).toLocaleTimeString(widget.locale, { hour: "2-digit", minute: "2-digit" });
  $("stale").hidden = !stale;
}

refresh();
setInterval(refresh, 30 * 60 * 1000);   // 30 分钟
document.addEventListener("visibilitychange", () => { if (!document.hidden) refresh(); });

要点：

  • permissions 要写 network:api.github.com（不是 *.github.com：能少就少）。
  • 先写画面再写数据，或像上面一样“失败也有东西可显示”，卡片不会一片空白。
  • 定时器用 setInterval 就好；不要每秒轮询，widget.media、widget.audio 这类有事件的就用 onChange。

  bar.appendChild(cell);
  if (bar.children.length > 20) bar.firstElementChild.remove();
}

.mini { display: flex; align-items: flex-end; gap: 1px; height: 1.6rem; }
.mini i { width: 2px; background: var(--w-accent); } /* 不要 transition / animation */

要点：

  • 每秒更新的元素不要 transition、不要 animation：一个 0.5 秒的动画等于整张卡片一直在重画，处理器会一直有负担。
  • 数字用 font-variant-numeric: tabular-nums，宽度不会随数字变动而抖。
  • 订阅用完要退订（const stop = widget.system.subscribe(...); stop()），否则卡片一直有取样成本。

例 3：同一个组件放两个，各记各的

// 卡片自己在拖动和缩放时会变，实例标识不会变：用它当数据分界
const key = `state:${widget.instanceId}`;

const saved = await widget.storage.get(key);
index = saved ? saved.index : 0;

function save() {
  widget.storage.set(key, { index });   // 不用 await，写入很快
}

要点：widget.storage 的键是组件级别的（同一组件的两个实例共用一个文件），要分开保存就在键里带上 instanceId；设置值（settings）则是每个实例各自一份。

写组件的检查列表

交付前逐条看一眼，能省掉九成的“装上去怪怪的”：

  • widget.json 的 id 只用小写英文、数字和 . _ -，2–64 字元，之后不再改。
  • entry 指向的文件真的存在；所有资源都用相对路径。
  • 文件存成 UTF-8（没有 BOM 也可以，有 BOM 会让 JSON 解析失败）。
  • 用到的能力都在 permissions 里声明；能用 network:某个网站 就不要 network:*。
  • 第一次加载就有东西看：先画版面，再等数据；取不到时给一句人话，不要空白。
  • 每秒更新的元素不加动画；不定时轮询已经有事件的功能。
  • 数字和日期用 widget.locale 格式化，文字用 widget.t()。
  • 只用 --w-* 变数和 w-* 样式，三套主题切一遍都不会看不到字。
  • 卡片可以被拉大缩小：用 flex/grid，必要时 @container；想让内容跟着放大就设 grow。
  • 不要写 window.open、页面跳转、document.write；要开网页用 widget.shell.open。
  • 不要引用 CDN 上的脚本或字体（离线就坏了），要打包进组件文件夹。
  • 送出前在开发者模式按 F12 看一遍 Console，没有红色错误再导出 .fwz。

常见问题

改了文件，桌面上没变化。 确认“设置”里开发者模式是开的。没开的话，在组件上右键 →“重新加载”。如果改的是 widget.json 而组件不见了，看“添加组件”页顶部是不是列出了错误。

**widget.fetch 失败，说 permission denied。** 把那个网站加进 permissions，例如 "network:api.example.com"。错误讯息里会写出要加的那一行。如果说 "not allowed yet"，表示已经声明但用户还没允许：到控制中心“我的组件”选这个组件，按“查看并允许”。

**直接用 fetch() 或 <img> 加载网络上的东西失败。** 网站要在 permissions 里。fetch() 还要对方支持 CORS；不支持的话改用 widget.fetch。

中文变成乱码。 把文件存成 UTF-8。

想让组件第一次出现时大一点或小一点。 改 size.width 和 size.height。已经在桌面上的组件会保留用户调过的大小，可以从“添加组件”再放一个新的来看效果。

怎样让组件在浅色主题（纸本）下也好看？ 文字和线条都用 --w-* 变数，不要写死白色或黑色。到控制中心“主题”切换三套主题看一遍。

改了“语言”设置，组件还是原本的语言。 语言在启动时读 config.json，改了要重新启动 WinWidget（控制中心“设置”里的语言会立即影响控制中心本身，桌面上已经开着的组件要重新加载才会换）。组件里请一律用 widget.locale / widget.t()，不要自己判断系统语言。

控制中心按“组件目录”“数据位置”没反应，提示“没有成功”。 这两个按钮由 WinWidget 用系统的方式打开文件夹（等同在资源管理器里双击）。如果完全没反应：先确认路径存在（按钮会自动建立目录），再看 %LocalAppData%\WinWidget\logs\app.log 里那一行错误。旧版本把文件夹当成网址开启，所以一定会失败，更新到最新版即可。

“检查更新”说没有更新通道 / 检查不到。 config.json 的 update_url 留空时，默认读本专案 GitHub Releases 的最新版本（api.github.com）。要换成自己的通道，就在 update_url 填一个 JSON 位址，内容是 {"version": "1.2.0", "url": "下载位址", "size": 文件大小, "notes": "更新说明", "page": "介绍页"}。检查和下载都在背景执行，不会让界面卡住；开发者模式不允许自我更新。

媒体组件里“显示是哪个程序在播放”关掉还有字。 那是组件页面自己的显示逻辑，最新版已修好。若还留着，确认组件文件夹里的 style.css 是最新的（body.no-app .app { display: none }）。

WinWidget 組件開發指南

一個組件就是一個資料夾：一個 widget.json 說明檔，加上普通的 HTML、CSS 和 JavaScript。會寫網頁，就會寫組件。

十分鐘寫第一個組件

我們來做一個「每日一句」：每天顯示一句話，按一下換下一句，句子可以在控制中心改。

1. 建立組件（1 分鐘）

  • 左鍵點托盤圖標，打開控制中心。
  • 到控制中心「添加組件」頁，按右上角的 新建組件…（視窗窄時只顯示「＋」圖標）。也可以右鍵系統匣圖標 →「添加組件」→「新建組件…」。
  • 名稱輸入 每日一句，按 建立。

WinWidget 會：

  • 在組件目錄建立一個資料夾（例如 %AppData%\WinWidget\widgets\my-widget），裏面是一個能用的模板；
  • 把它放到桌面；
  • 打開 開發者模式：之後改了資料夾裏的檔案，一存檔，桌面上的組件就會自動重新載入；
  • 用檔案總管打開這個資料夾。

用你習慣的編輯器打開這個資料夾。推薦 VS Code：資料夾裏的 widget.d.ts 會讓它在你打 widget. 時列出所有可用的功能和說明。

2. 加一個設定項（1 分鐘）

打開 widget.json，把 settings 整段換成：

"settings": [
  { "key": "quotes", "type": "textarea", "label": "句子（一行一句）",
    "default": "慢慢來，比較快。\n今天也要好好吃飯。\n先完成，再完美。" }
]

存檔。打開控制中心 →「我的組件」→ 選「每日一句」→「內容」，會看到一個多行文字框，裏面是這三句話。這個表單是 WinWidget 照 settings 自動生成的。

3. 寫畫面（3 分鐘）

把 index.html 換成：

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="w-label" id="day"></div>
  <p class="quote" id="quote"></p>
  <button class="w-btn" id="next">換一句</button>
  <script src="main.js"></script>
</body>
</html>

把 style.css 換成：

body {
  display: flex;
  flex-direction: column;
  gap: 8px;
}

.quote {
  flex: 1;
  margin: 0;
  font-size: 1.3rem;
  line-height: 1.5;
}

#next {
  align-self: flex-end;
}

<body> 就是那張卡片。w-label、w-btn 是 WinWidget 自帶的樣式，背景、圓角、字體和顏色由主題提供，你不用寫。

4. 寫邏輯（3 分鐘）

把 main.js 換成：

const $ = (id) => document.getElementById(id);
let quotes = [];
let index = 0;

function show() {
  const quote = quotes.length ? quotes[index % quotes.length] : "到控制中心加幾句話吧";
  $("quote").textContent = quote;
  $("day").textContent = new Date().toLocaleDateString(widget.locale, {
    month: "long", day: "numeric", weekday: "long",
  });
}

// 讀設定：一行一句
function load(settings) {
  quotes = settings.quotes.split("\n").map((s) => s.trim()).filter(Boolean);
  show();
}

// 每天自動換一句；按過「換一句」的話，記住今天換到哪一句
const today = new Date().toDateString();
widget.storage.get("pick").then((pick) => {
  const dayNumber = Math.floor(Date.now() / 86400000);
  index = pick && pick.day === today ? pick.index : dayNumber;
  load(widget.settings.get());
});

// 用戶在控制中心改了句子，馬上更新
widget.settings.onChange(load);

$("next").addEventListener("click", () => {
  index++;
  widget.storage.set("pick", { day: today, index });
  show();
});

存檔，桌面上的組件馬上變成新的樣子。試試：

  • 按「換一句」；
  • 在控制中心改句子，桌面上即時更新；
  • 到「主題」換一套主題，組件的字體和顏色會跟着變；
  • 重新啟動 WinWidget，今天換到的那一句還在（widget.storage 會一直保存）。

5. 出錯了怎麼辦（1 分鐘）

開發者模式下，腳本出錯時卡片底部會出現一條紅色提示，寫着錯誤和位置（例如 main.js:12）。點一下它就會打開開發者工具；也可以在組件上按 F12。改好存檔，提示就會消失。

6. 分享出去（1 分鐘）

控制中心 →「添加組件」→ 你的組件卡片 →「匯出 .fwz」。別人雙擊這個 .fwz 檔案就能安裝（也可以拖到控制中心視窗上）。

想讓所有人都能在控制中心的「線上」裏找到它，可以投稿到組件市場：把組件資料夾放進 GitHub 上 fullwidget-market 儲存庫的 widgets/你的帳號.組件名/，開一個 pull request。自動檢查通過、維護者看過後就會上架，詳細步驟見那裏的 CONTRIBUTING.md。

資料夾裏有什麼

檔案用途
widget.json說明檔：名稱、尺寸、權限、設定項。必須有。
index.html組件的頁面（可以在 widget.json 的 entry 改成別的檔名）。
style.css、main.js樣式和邏輯。檔名隨意，在 HTML 裏用相對路徑引用即可。

name建議顯示的名稱。可以是文字，也可以按語言給：{ "zh-TW": "…", "en": "…" }。
description一句話介紹，顯示在組件庫。同樣可以按語言給。
version建議版本號，例如 1.2.0。安裝 .fwz 時用它判斷是更新、重新安裝還是舊版本。

preview組件庫卡片上的預覽圖，例如 "preview.png"。可以按主題和語言各放一張："preview/{theme}.{lang}.webp"，{theme} 換成主題 id（instrument、type、paper），{lang} 換成 zh-TW、zh-CN 或 en；缺的那張會用同主題的其他語言，或其他主題代替。圖片建議用透明背景的 PNG 或 WebP，寬 300 像素左右。沒有的話卡片顯示圖標。

layer第一次放上桌面時的層級：desktop（預設，在所有視窗下面，Win+D 也看得到）、normal、top（置頂）。用戶之後可以改。
permissions要用到的權限，見權限。
settings設定項。控制中心會照這裏自動生成表單。

JavaScript API

WinWidget 會在你的腳本執行前準備好全局的 widget，不用 import。完整的型別和說明在 widget.d.ts。

需要等待的功能（讀寫資料、連網等）都回傳 Promise，可以用 await。

基本資料

widget.id          // "me.daily-quote"
widget.instanceId  // 桌面上這一個的識別碼（同一個組件可以放幾個）
widget.locale      // 用戶的語言，例如 "zh-TW"，格式化日期和數字用
widget.theme       // 目前的主題："instrument"、"type"、"paper"
widget.developer   // 是否在開發者模式
widget.permissions // 現在能用的權限

// 按用戶的語言挑文字
widget.t({ "zh-TW": "早安", "zh-CN": "早安", en: "Good morning" })

設定：widget.settings

// 讀設定：同步的，不用 await
const all = widget.settings.get();         // { quotes: "…", … }
const one = widget.settings.get("quotes");

// 用戶在控制中心改了設定
widget.settings.onChange((all) => { /* … */ });

// 程式也可以改，控制中心會同步顯示
await widget.settings.set("quotes", "…");

保存資料：widget.storage

保存的東西重開電腦也在；用戶移除這個組件時一起刪除。桌面上每一個組件各有自己的一份。上限每個 2 MB。

// 可以存任何 JSON 資料
await widget.storage.set("todo", [{ text: "買牛奶", done: false }]);

// 沒存過的是 null
const todo = (await widget.storage.get("todo")) || [];

await widget.storage.remove("todo");
const keys = await widget.storage.keys();

系統資訊：widget.system（需要 system 權限）

const stop = widget.system.subscribe(["cpu", "memory"], (d) => {
  cpu.textContent = Math.round(d.cpu.usage) + "%";
  mem.textContent = Math.round(d.memory.usage) + "%";
}, { interval: 2000 });  // 每 2 秒一次，預設 1 秒；第一筆會馬上到

stop(); // 不需要時停止
主題內容
cpuusage（%）、cores
memoryusage（%）、total、used、available（位元組）
networkdown、up（每秒位元組）、totalDown、totalUp
disk每個磁碟一項（含隨身碟）：name（"C:"）、label、type（fixed / removable）、total、free、usage（%）
batterypresent、percent、charging、pluggedIn、secondsLeft、saver（省電模式）

多個組件訂閱同一個數據時，WinWidget 只取樣一次，不會多耗資源。

不常變的資料用一次性的呼叫：

const pc = await widget.system.info();
// pc.os.name "Windows 11 Pro"、pc.os.version "25H2"、pc.cpu.name、pc.memory.installed（位元組）、
// pc.gpus（顯示卡名稱）、pc.computer（電腦名稱）、pc.uptime（已開機的毫秒數）

const net = await widget.system.adapters();
// net.online；net.adapters[0] 是連上網路的那個：name "Wi-Fi"、type "wifi"、ipv4、gateways、dns

const r = await widget.system.ping("1.1.1.1");   // { ok, ms, status }；每個組件每秒最多一次

音量：widget.audio（需要 audio 權限）

const stop = widget.audio.onChange((a) => {
  // a.volume 0–100、a.muted、a.device（"喇叭 (Realtek Audio)"）
  // 按鍵盤的音量鍵、工作列調音量、換成耳機時都會馬上通知
});
await widget.audio.set({ volume: 40 });
await widget.audio.set({ muted: true });

正在播放：widget.media（需要 media 權限）

讀取 Windows 媒體控制裏正在播放的內容（Spotify、瀏覽器、媒體播放器……，和音量面板上看到的一樣），並控制它：

widget.media.onChange((m) => {
  if (!m.available) return;          // 沒有程式在播放
  // m.title、m.artist、m.album、m.app.name（"Spotify"）、m.app.icon
  // m.playing、m.position、m.duration（毫秒）、m.cover（封面圖片的網址，可直接放進 <img>）
  // m.can.next、m.can.previous、m.can.seek：那個程式現在接受哪些按鈕
});
const now = widget.media.position(m);   // 現在播到哪裏（播放中會自己往前走）
await widget.media.toggle();            // 播放 / 暫停；也有 play()、pause()、next()、previous()
await widget.media.seek(60000);         // 跳到 1:00
// 目前這首歌的時間軸歌詞，在網易雲音樂、QQ 音樂、酷狗上查找
const { title, lyrics } = await widget.media.lyrics();
if (lyrics.found) lyrics.lines;         // [{ t: 毫秒, text, tr?: 翻譯 }]，按時間排好

Windows 有變化時會馬上通知（換歌、暫停、換了一個程式在播放），不用自己輪詢。

讀取用戶選的資料夾：widget.files

在設定項裏放一個 folder 類型的設定，用戶選了資料夾，組件就能讀取裏面的圖片。選資料夾本身就是允許，不用在 permissions 聲明：

{ "key": "folder", "type": "folder", "label": "照片資料夾", "default": "%USERPROFILE%\\Pictures" }
const { files } = await widget.files.list("folder", { recursive: true });
// files: [{ path: "2025/海邊.jpg", name: "海邊", size, modified, url }]
img.src = widget.files.url(files[0], { width: 800 });   // Windows 做的縮小版，大照片也很快、很省記憶體
const { taken } = await widget.files.info("folder", files[0]);  // 拍攝時間（相機記錄的），沒有時是 null
await widget.files.pick("folder");      // 在組件裏直接打開選資料夾的視窗，選好後存進設定

生命週期：ready → show → hide → unload

一張卡片從被載入到被移除，外殼會按固定順序發事件。全部用 widget.on(名稱, 回呼) 訂閱，回傳值是退訂函式。

事件什麼時候來內容
ready頁面起來了（DOMContentLoaded 之後再過一個工作，所以你寫在 DOMContentLoaded 裡的訂閱一定聽得到）{ visible }
show卡片出現在螢幕上。開機那次也算一次，帶 initial: true{ from, visible: true, initial }
hide卡片離開螢幕：隱藏全部、托盤單張隱藏、全螢幕讓位、window.hide(){ from, visible: false, initial: false }
resize卡片尺寸變了（拖邊、拖角、控制中心改大小）。連續變化會去抖 80ms，只回報停下來的那一個{ width, height }，CSS 像素
unload卡片要被移除、或整個程式要結束{ kill: true }

from 說明這次顯示/隱藏是誰造成的：

from誰
startup開機跟著外殼一起顯示
tray托盤選單（顯示/隱藏全部、單張顯示/隱藏）
control控制中心（「定位」、顯示全部開關）
hotkey全域快捷鍵叫出來
fullscreen有別的全螢幕程式，這張卡片讓開或回來
api卡片自己呼叫 widget.window.show() / hide()

順序保證

  • ready 一定比第一個 show 早。所以「啟動時要做一次」的初始化寫在 ready 裡，不會被 show 打亂。
  • 已經在螢幕上的卡片（開機預設）會在 ready 後立刻收到 show{ initial: true }；啟動時被隱藏的（例如開了「隱藏全部」）不會收到，等真的顯示才有。
  • show / hide 是成對的，而且同一個狀態不會重複發：hide 之後再 hide 沒有第二次；show 之後再 show 也沒有。用 widget.visible 隨時查目前狀態。
  • hide 會在卡片仍活著的時候到，unload 是「這次真的要走了」。只做一次的事（存檔、關定時器）放 unload，暫停動畫放 hide。
// 邊跑邊省電：看不見就停，回來再算一次
let timer = 0;
function start() {
  if (timer || !widget.visible) return;
  timer = setInterval(tick, 1000);
  tick();
}
function stop() {
  clearInterval(timer);
  timer = 0;
}

widget.on("ready", () => start());
widget.on("show", ({ from, initial }) => {
  widget.log("shown", from, initial);   // from 見上表
  start();
});
widget.on("hide", () => stop());
widget.on("unload", ({ kill }) => {
  stop();
  if (kill) widget.storage.set("lastSeen", Date.now());
});

// 尺寸變了再排版（不用聽 window 的 resize，那是整窗，帶 DPI 換算）
widget.on("resize", ({ width, height }) => {
  document.body.dataset.compact = width < 260 ? "1" : "";
});

widget.visible 是隨時可讀的目前狀態，SDK 會跟著 show / hide 更新。卡片刻意不去搶鍵盤焦點，所以沒有 focus / blur 事件；要用鍵盤輸入的組件，自己在卡片裡放輸入框，使用者點它才會拿到鍵盤。

和 uTools 那七個事件的對照

uTools 的事件是「外掛程式 vs 主視窗」的模型；WinWidget 的卡片本身就是一個獨立視窗，所以只能對到形狀相同的那幾個：

uToolsWinWidget差在哪
onPluginReady(cb)widget.on("ready", cb)一樣只在載入後一次。uTools 會等 cb 的 Promise；這裡不會等，要「等完再進」用 utools.onPluginReady
onPluginEnter(cb)widget.on("show", cb)參數形狀見下；每次顯示都觸發，不只是第一次
onPluginOut(cb)widget.on("hide", cb) + widget.on("unload", cb)hide 對應 isKill: false，unload 對應 isKill: true
onPluginDetach(cb)無卡片本來就是獨立視窗，沒有「分離」這一步；utools.onPluginDetach 會登記但不觸發
onScheduleTrigger(cb)utools.onScheduleTrigger(cb)一樣。自寫的 cron 到點會真的調 cb，{ code, label, at }
onMainPush(cb, onSelect?)utools.onMainPush(cb)有，語意是「帶著 payload 被喚起」：redirect(label, payload) 命中本組件的動態功能後，向被喚起的那張卡片推 mainPush，cb(action, payload) 收 { code, type, payload, from }。onSelect 不實作（沒有結果列表可選）
onDbPull(cb)utools.onDbPull(cb)有，但是降級：沒有雲端，只是同一個組件的其他卡片改了文檔時，向本組件的每張卡片廣播 { direction: "pull", docs: [...] }

utools.onPluginEnter 的參數按 uTools 的 PluginEnterAction 給：{ code, type: "text", payload: "", from }，from 是 uTools 的詞（main / panel / hotkey / redirect），由上表的 from 映射過來：startup、fullscreen → main，tray → panel，hotkey → hotkey，control、api → redirect。option 只有在「從推送結果進來」時才有，這裡不會有。

開自己的視窗：createBrowserWindow

卡片本身是 uTools 說的 main window（utools.getWindowType() → "main"）。要開設定面板、預覽窗、全螢幕展示這種第二個視窗，用 utools.createBrowserWindow(url, options, callback)：定義照 uTools / Electron 的 BrowserWindow，同一份頁面在這種視窗裏 getWindowType() → "custom"。

const win = utools.createBrowserWindow(
  "panel.html?mode=edit",              // 組件資料夾裏的 HTML，可以帶 query
  {
    width: 520, height: 380,           // 頁面區域，不含標題列
    title: "設定",
    show: false,                       // 先別露面，等 callback 再顯示，避免白屏
    resizable: true,
    alwaysOnTop: true,
    backgroundColor: "#0f1a24",
  },
  (w) => {
    w.show();                                    // 頁面 ready 了才顯示
    w.webContents.send("hello", "從卡片來");      // 卡片 → 視窗
  }
);
win.on("closed", () => widget.log("視窗被關掉"));

這個視窗是什麼

  • 它是同一個組件的頁面：同一個 origin（<組件 id>.widgets.localhost）、同一份 localStorage、同一套主題和 SDK。所以 widget.storage、widget.settings、utools.dbStorage 兩邊看到的是同一份資料。
  • 頁面裏 widget.windowType === "custom"、widget.windowId 是這個視窗的號碼；utools.getWindowType() 回 "custom"。卡片那邊是 "main"、windowId 是 0。
  • 號碼從 1 開始，一個組件同時最多 24 個視窗。
  • 卡片被移除、或整個程式結束時，它開的視窗一起關掉（先關子視窗，再關父視窗）。

外觀：跟着主題走

WinWidget 有幾套主題，用戶也能在控制中心調整背景、文字顏色、強調色、字體、字號、圓角、內距和透明度。只要你的組件用下面這些變數和樣式，這一切都會自動生效。

版面

  • <body> 就是卡片：背景、圓角、邊框、內距都已經設好。內容直接放進 <body>。
  • <html> 是透明的視窗，四周留了給陰影的空白，不要給它加背景。
  • 字號用 rem：用戶調「字號」時，1rem 會跟着變（預設 14px）。
  • 卡片可能被縮放。用 flex/grid 排版；要按大小調整，可以在 body 上設 container-type: size，再用 @container (max-height: 100px) { … }。注意 @container 只能改 body 裏面的元素，改不了 body 本身。

放大時內容跟着變大

在 widget.json 的 size 加上 "grow": 1，用戶把卡片拉得比預設大時，整張卡片的內容會一起放大，字、圖標、間距都按比例變大，不會只是多出空白：

"size": { "width": 260, "height": 150, "minWidth": 180, "minHeight": 110, "grow": 1 }
  • 放大的倍數是「寬放大幾倍」和「高放大幾倍」中較小的那個，最多 3 倍。例如拉到兩倍寬、1.3 倍高，內容放大 1.3 倍，多出來的寬度交給你的排版。
  • 比預設小時不會縮小，小尺寸要靠你自己的排版（上面的 @container）。
  • grow 可以是 0 到 1 之間：清單類的組件寫 0.5，拉大時字變大一點，同時多顯示幾項。
  • 不寫或寫 0：和以前一樣，只是多出空間。
  • 卡片的圓角、邊框和陰影不會跟着放大。目前的倍數在 CSS 變數 --w-size-scale。

省電：每秒更新的東西不要加動畫

組件整天開着，每一幀畫面都要算。每秒更新一次的數字或進度條，如果加了 0.5 秒的 transition，畫面就幾乎一直在動，一個組件可以吃掉 20% 的處理器核心；不加的話只要 1%。

  • 每秒或更頻繁更新的元素，不要 transition 和 animation。w-bar 預設有 0.5 秒的寬度動畫，每秒更新時寫 .w-bar > i { transition: none; }。
  • 不要 animation: … infinite；要閃爍提示，給一個次數（例如 8）。
  • 指針、轉盤這類要轉的東西，放在獨立的元素上用 CSS transform 轉，不要每秒重畫整個 SVG。
  • 每分鐘才變的東西，就每分鐘才更新（setTimeout 對準下一分鐘）。

拖動、選單和點擊

WinWidget 已經幫你處理好：

  • 拖動：在卡片任何地方按住拖動，就能移動組件。按鈕、連結、輸入框不會觸發拖動；其他元素不想被拖動時，加上 data-no-drag。
  • 右鍵：顯示 WinWidget 的組件選單。某個區域要自己處理右鍵時，加上 data-no-menu。
  • 縮放：size.resizable 不是 false 時，右下角會有縮放手把。
  • 鎖定：用戶鎖定組件後不能拖動和縮放；你可以用 widget.locked 和 html[data-locked] 知道。

誰來允許：

  • 用「新建組件」建立的組件是你自己寫的，聲明的權限直接生效。
  • 別人的組件，安裝時會列出它要的權限，用戶按「安裝」才算允許。更新後多要了權限，用戶要再允許一次，在那之前新權限用不了。

除錯

在控制中心「設定」打開 開發者模式（用「新建組件」時會自動打開）。打開後：

  • 沒有載入的組件：widget.json 寫錯（例如少了逗號、id 不合規則、找不到入口檔），「添加組件」頁頂部會列出是哪個資料夾、哪一行、什麼問題。

打包和分享

.fwz 就是把組件資料夾壓成 zip、改了副檔名。

  • 匯出：控制中心「添加組件」→ 你的組件卡片 →「匯出 .fwz」。隱藏的檔案和資料夾（例如 .git）以及 node_modules 不會被打包。
  • 安裝：雙擊 .fwz 檔案、把它拖到控制中心視窗上，或在「添加組件」按「安裝 .fwz 檔案…」。安裝前會顯示名稱、作者、版本和需要的權限。
  • 更新：改大 version 再匯出。id 相同的組件會被替換，桌面上的組件、設定和保存的資料都會保留；舊版本移到資源回收筒。
  • 用框架寫：React、Vue、Svelte 都可以，只要輸出靜態檔案。把建置結果（例如 dist/）和 widget.json 放在一起，entry 指向它的 index.html；資源路徑要用相對路徑（例如 Vite 設 base: "./"）。
  • 大小限制：.fwz 最大 64 MB，解壓後最多 256 MB、5000 個檔案。

裝 uTools 外掛（.upx）

同一個「安裝 .fwz / .upx…」按鈕（以及拖放到控制中心）也認 uTools 的 .upx。它其實是 gzip 包著「16 位元組頭 + JSON 目錄 + 4 位元組對齊 + 檔案資料」，WinWidget 會就地拆開，用 plugin.json 生成一份 widget.json：

plugin.json變成
name（一串小寫字母數字）id；缺失或不合規時按 pluginName 散列成 uplugin-xxxxxxx
pluginNamename（中文名照原樣顯示）
main / logoentry / icon
version / author / description同名欄位
features / preload記在 widget.json 的 utools 區塊裡，僅作留痕

權限是從頁面程式碼裡掃出來的（看到 utools.copyText 就給 clipboard，看到 utools.screen.* 就給 screen，依此類推），安裝前的確認框會照常列出來讓你決定。

一個已知的天花板：uTools 的 preload.js 跑在 Node.js 裡，而 WinWidget 的頁面跑在 WebView2 裡，沒有 Node。所以純網頁外掛（HTML + JS + jQuery 之類）能直接跑；依賴 preload 的外掛裝得進來、頁面也能開，但 preload 提供的能力不可用。日誌裡會寫一條 upx: "…" declares preload.js — Node.js is not available in this host。

.upxs：新版市場安裝包讀不了，從已安裝的外掛轉過來

uTools 自 5.0.0 起把市場安裝包換成了 .upxs：整包加密、附開發者簽名，用來保證「來自可信任開發者、沒被改過」。WinWidget 沒有這把鑰匙，所以拖 .upxs 進來只會得到一句明確的提示，而不是假裝解包成功：

沒辦法安裝這個檔案
this is a uTools UPXS package (encrypted and signed since uTools 5.0).
WinWidget has no key for it, so the files cannot be read here.

官方 changelog 的原話是「安裝包格式升級為 UPXS 格式。這一格式不僅具有加密功能，還包含開發者資訊簽名」。實測那個 1.6 MB 的檔案，除了頭 4 個位元組（c8 01 00 00）之外整塊熵值都是 8.0，找不到 zip／gzip／JSON 的任何痕跡，也不是異或那種能靠頻率分析還原的東西。

可行的路子是先在 uTools 裡裝好，再把裝好的外掛搬過來：uTools 解出來的外掛放在 %APPDATA%\uTools\plugins\，是一個個 .asar（Electron 的封存，沒有加密）。WinWidget 直接認這種檔案：

  • 在 uTools 裡正常安裝那個外掛；
  • 到 %APPDATA%\uTools\plugins\ 找到對應的 <一串 hash>.asar（不確定是哪個就用「添加組件」頁的匯入按鈕逐個試，安裝確認框會顯示外掛名）；
  • 在控制中心「添加組件」→「安裝 .fwz / .upx…」選中它，或者直接把 .asar 拖到控制中心。

.asar 的頭是 [u32 4][u32 pickle][…][u32 jsonLen]，資料區從 8 + pickle 開始，目錄項是 {size, offset:"…", unpacked?, link?}——和 .upx 只差一個頭，所以兩者共用同一套「拆包 → 用 plugin.json 合成 widget.json」的流程。帶 unpacked 標記的檔案（原生模組之類）從旁邊的 <名字>.asar.unpacked\ 目錄讀。

順帶說明：utools.getAppVersion() 報的是相容級別（目前 7.6.0），不是 WinWidget 自己的版本號。外掛普遍寫 parseFloat(utools.getAppVersion()) < 7 判斷底座夠不夠新，報 1.0.0 會讓它們直接畫一張「uTools 版本太低」的頁面擋住一切。

帶 preload.js 的外掛：window.services 接橋

uTools 的 preload.js 跑在 Electron 的 preload 裡，require("fs")、require("electron") 都有；WinWidget 的頁面在 WebView2 裡，沒有 Node。所以帶 preload 的外掛以前會白屏——頁面第一次碰 window.services.xxx() 就拋 Cannot read properties of undefined，整頁 React 掛不上去。

現在宿主會往每個組件頁注入 services.js（在 utools.js 之後），用同名的方法把 window.services 接成宿主橋：

preload 裡的方法現在由誰答
readAllRecords / removeRecords / clearAllRecords宿主的剪貼板歷史：clipboard.history，存在 data\clipboard-history.json（最近 300 條，文字和檔案）
listenAppendRecord(cb)宿主每 700ms 掃一次剪貼板，有新內容就推給頁面
filesExists(paths)clipboard.filesExist
executeCopy / executePaste轉給 utools.copyText / copyFile / hideMainWindowPasteText / hideMainWindowPasteFile
dragToFiles、pinScreen、mcpPinData 等目前只是 no-op，會在控制台留一行「not bridged」

window.services 只有在頁面自己沒有時才會被裝上；頁面裡已經有自己的橋就不動它。

實測（uTools 的「剪貼板」外掛，69699f4f…asar）：卡片開出來是正常的列表，複製任何東西都會立刻出現在最上面，檔案記錄顯示「1 個檔案」，點條目複製／貼上都可用。還差的部分寫在下面。

兩點值得記住：

  • 歷史只在宿主執行期間記錄。想抓更早的內容，得先有頁面在跑（第一次 clipboard.history 會啟動監聽）。圖片暫時不收，所以「圖像」那一欄是空的。
  • 裝包時的確認框就是授權。以前匯入完成只寫 permissions，使用者還得自己到控制中心點「允許」；現在安裝會把確認框裡列出的權限寫進 grants，並把已經開著的舊頁面重載一遍，不會再出現「裝好了但每個呼叫都 permission denied」。

還沒接的：setSubInput（外掛頂部的搜尋框，uTools 宿主自己畫的）、釘圖／貼邊視窗、把記錄拖成檔案。

剪貼板歷史：一套給 JS 用的完整介面

宿主自己維護一份歷史（data\clipboard-history.json，最近 300 條，type 為 text / image / files，最新在前），並把讀寫都攤成方法。組件裡用 widget.clipboard.*，uTools 外掛裡用 window.services.*：

方法（widget.clipboard.*）參數作用
history(opts){type, pinned, limit}取記錄；type 是 text/image/files/all，pinned 只看收藏
stats()—{all, text, image, files, pinned}，就是四個分類標籤上的數字
pin(ids, pinned)記錄 id 或 hash 的陣列收藏／取消收藏（pinned 預設 true）
remove(ids)同上刪除若干條
clear(opts){keepPinned}清空；keepPinned: true 只留收藏
copy(id)記錄 id把這條塞回系統剪貼板
image(id)記錄 id圖片記錄的 PNG data URL

對應的宿主方法名是 clipboard.history / .stats / .pin / .remove / .clear / clipboard.recopy / clipboard.image / clipboard.filesExist，都要求 clipboard 權限。

「執行貼上」不需要新介面：utools.hideMainWindowPasteText/File/Image 已經是「收起卡片 → 還原前景視窗 → Ctrl+V」，剪貼板裡放了什麼就貼什麼，所以 copy 之後呼叫它就行。

圖片記錄怎麼落地：截圖進剪貼板時，宿主把 PNG 存到 data\clipboard\images\<hash>.png，記錄裡 value 記路徑、size 記位元組數。uTools 的外掛是按 utools.db.getAttachment("attachment/" + hash) 取圖的，所以頁面第一次讀到這條記錄時，services.js 會把位元組補傳成該組件自己的附件（attachment/<hash>），再把 value 改寫成附件 id——列表縮圖和收藏流程就都走同一條路。

收藏是兩條腿：外掛自己用 collect/<hash> 文件 + utools.db.promises.allDocs("collect/") 記一份，宿主記錄上另有 pinned 欄位（clipboard.history.pin）。為了讓前者能用，utools.js 的 db.allDocs 現在接受前綴字串（以前只認 {idStartsWith}），db.getAttachment 回傳的物件也帶上了 buffer / byteLength / length（uTools 給的是 Node Buffer，外掛普遍寫 new Blob([n.buffer])），db.postAttachment 收 ArrayBuffer / TypedArray。

WinWidget 的能力劃分跟 uTools 官方文件一致，頁面上用 utools.* 的名字。這一節按分類給最小例子；型別都在 widget.d.ts 的 WinWidget.Utools 裡。

和 uTools 插件的關係（相容到哪一步）

uTools 的插件是 Electron 應用：plugin.json + preload.js（在 Node 環境裏 require("fs")、裝 Sharp / FFmpeg）+ 頁面。WinWidget 是 Rust + WebView2，沒有 Electron，也沒有 Node，所以 uTools 插件不可能原樣搬進來。能搬的是「頁面 + 頁面上呼叫 utools.* 的那部分能力」：每個組件頁都會被注入一份 utools 相容層（/__fw/utools.js），把它接到 WinWidget 自己的宿主能力上。

想把一個現成 uTools 插件的畫面搬進來

  • 把插件的 index.html、CSS、JS 放進一個組件資料夾；
  • 在 widget.json 裏按它用到的能力聲明 permissions（showNotification → notify、copyText → clipboard、captureScreen → screen、shellOpenPath → shell.launch、shellOpenExternal → shell.open）；
  • 頁面上呼叫的 utools.* 由相容層處理，不必改程式碼。

不要指望：preload.js、require(...)、process、fs、child_process。這些在 WinWidget 裏不存在，把 preload 原封不動搬進來只會得到一片空白。頁面上用到的 ipcRenderer 有相容層（見「開自己的視窗」那一章），它背後是本組件的視窗訊息，不是 Electron 的行程間通訊。

和外殼怎麼對接（進階）

前面幾章的寫法已經能做出完整的組件。這一章寫給想知道「它到底怎麼跑起來」的人：頁面從哪來、外殼塞了什麼進來、有哪些訊息、資料放在哪。看清楚這些，除錯和做進階功能都會快很多。

頁面是怎麼被載入的

WinWidget 不是用 file:// 打開你的 index.html，而是啟動一個只綁定 127.0.0.1 的小型 HTTP 服務，頁面由它提供：

http://127.0.0.1:<連接埠>/__fw/<組件 id>/index.html
  • 連接埠每次啟動都可能不同，所以永遠寫相對路徑（style.css、main.js、img/a.png），不要寫死 127.0.0.1:8800。
  • 每一種組件有自己的 origin：<組件id>.widgets.localhost。localStorage、IndexedDB、Cache 都按 origin 隔離，同一種組件的多個實例共用這一份。
  • 頁面不能自行跳轉到別的網址，也不能開新視窗；要開網頁請用 widget.shell.open。
  • 頁面裏載入的圖片、字體、腳本，同樣受 permissions 的 network: 限制。

三個完整例子

例 1：把一個網路 API 的數字放上桌面

需求：顯示某個 GitHub 專案的 star 數，每 30 分鐘更新，斷網時顯示上次的值。

widget.json 重點："permissions": ["network:api.github.com"]。

const $ = (id) => document.getElementById(id);
const KEY = "last";

async function fetchOnce() {
  const r = await widget.fetch("https://api.github.com/repos/Demon1110/WinWidget", {
    headers: { accept: "application/vnd.github+json" },
  });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const repo = await r.json();
  return { stars: repo.stargazers_count, at: Date.now() };
}

async function refresh() {
  try {
    const data = await fetchOnce();
    show(data, false);
    await widget.storage.set(KEY, data);
  } catch (e) {
    // 失敗時退回上次的值，並在角落標一下「舊資料」
    const old = await widget.storage.get(KEY);
    if (old) show(old, true);
    else $("stars").textContent = "—";
    widget.log(`stars: ${e.message}`);
  }
}

function show(data, stale) {
  $("stars").textContent = data.stars.toLocaleString(widget.locale);
  $("at").textContent = new Date(data.at).toLocaleTimeString(widget.locale, { hour: "2-digit", minute: "2-digit" });
  $("stale").hidden = !stale;
}

refresh();
setInterval(refresh, 30 * 60 * 1000);   // 30 分鐘
document.addEventListener("visibilitychange", () => { if (!document.hidden) refresh(); });

要點：

  • permissions 要寫 network:api.github.com（不是 *.github.com：能少就少）。
  • 先寫畫面再寫資料，或像上面一樣「失敗也有東西可顯示」，卡片不會一片空白。
  • 定時器用 setInterval 就好；不要每秒輪詢，widget.media、widget.audio 這類有事件的就用 onChange。

例 2：每秒更新的系統監控（省電寫法）

const $ = (id) => document.getElementById(id);
const bars = [];

// 一次訂閱兩個主題；WinWidget 會合成一筆資料給你
widget.system.subscribe(["cpu", "memory"], (d) => {
  if (d.cpu) {
    $("cpu").textContent = `${Math.round(d.cpu.usage)}%`;
    push(bars[0], d.cpu.usage);
  }
  if (d.memory) {
    $("mem").textContent = `${Math.round(d.memory.usage)}%`;
    push(bars[1], d.memory.usage);
  }
}, { interval: 1000 });

/** 20 格的迷你曲線；每秒更新，所以不加 transition。 */
function push(bar, value) {
  const cell = document.createElement("i");
  cell.style.height = `${Math.max(4, Math.min(100, value))}%`;
  bar.appendChild(cell);
  if (bar.children.length > 20) bar.firstElementChild.remove();
}
#cpu, #mem { font-variant-numeric: tabular-nums; }   /* 數字不會左右跳 */
.mini { display: flex; align-items: flex-end; gap: 1px; height: 1.6rem; }
.mini i { width: 2px; background: var(--w-accent); } /* 不要 transition / animation */

要點：

  • 每秒更新的元素不要 transition、不要 animation：一個 0.5 秒的動畫等於整張卡片一直在重畫，處理器會一直有負擔。
  • 數字用 font-variant-numeric: tabular-nums，寬度不會隨數字變動而抖。
  • 訂閱用完要退訂（const stop = widget.system.subscribe(...); stop()），否則卡片一直有取樣成本。

例 3：同一個組件放兩個，各記各的

// 卡片自己在拖動和縮放時會變，實例識別碼不會變：用它當資料分界
const key = `state:${widget.instanceId}`;

const saved = await widget.storage.get(key);
index = saved ? saved.index : 0;

function save() {
  widget.storage.set(key, { index });   // 不用 await，寫入很快
}

要點：widget.storage 的鍵是組件級別的（同一組件的兩個實例共用一個檔案），要分開保存就在鍵裏帶上 instanceId；設定值（settings）則是每個實例各自一份。

寫組件的檢查清單

交付前逐條看一眼，能省掉九成的「裝上去怪怪的」：

  • widget.json 的 id 只用小寫英文、數字和 . _ -，2–64 字元，之後不再改。
  • entry 指向的檔案真的存在；所有資源都用相對路徑。
  • 檔案存成 UTF-8（沒有 BOM 也可以，有 BOM 會讓 JSON 解析失敗）。
  • 用到的能力都在 permissions 裏聲明；能用 network:某個網站 就不要 network:*。
  • 第一次載入就有東西看：先畫版面，再等資料；取不到時給一句人話，不要空白。
  • 每秒更新的元素不加動畫；不定時輪詢已經有事件的功能。
  • 數字和日期用 widget.locale 格式化，文字用 widget.t()。
  • 只用 --w-* 變數和 w-* 樣式，三套主題切一遍都不會看不到字。
  • 卡片可以被拉大縮小：用 flex/grid，必要時 @container；想讓內容跟着放大就設 grow。
  • 不要寫 window.open、頁面跳轉、document.write；要開網頁用 widget.shell.open。
  • 不要引用 CDN 上的腳本或字體（離線就壞了），要打包進組件資料夾。
  • 送出前在開發者模式按 F12 看一遍 Console，沒有紅色錯誤再匯出 .fwz。

常見問題

改了檔案，桌面上沒變化。 確認「設定」裏開發者模式是開的。沒開的話，在組件上右鍵 →「重新載入」。如果改的是 widget.json 而組件不見了，看「添加組件」頁頂部是不是列出了錯誤。

**widget.fetch 失敗，說 permission denied。** 把那個網站加進 permissions，例如 "network:api.example.com"。錯誤訊息裏會寫出要加的那一行。如果說 "not allowed yet"，表示已經聲明但用戶還沒允許：到控制中心「我的組件」選這個組件，按「查看並允許」。

**直接用 fetch() 或 <img> 載入網路上的東西失敗。** 網站要在 permissions 裏。fetch() 還要對方支援 CORS；不支援的話改用 widget.fetch。

中文變成亂碼。 把檔案存成 UTF-8。

想讓組件第一次出現時大一點或小一點。 改 size.width 和 size.height。已經在桌面上的組件會保留用戶調過的大小，可以從「添加組件」再放一個新的來看效果。

怎樣讓組件在淺色主題（紙本）下也好看？ 文字和線條都用 --w-* 變數，不要寫死白色或黑色。到控制中心「主題」切換三套主題看一遍。

改了「語言」設定，組件還是原本的語言。 語言在啟動時讀 config.json，改了要重新啟動 WinWidget（控制中心「設定」裏的語言會立即影響控制中心本身，桌面上已經開着的組件要重新載入才會換）。組件裏請一律用 widget.locale / widget.t()，不要自己判斷系統語言。

控制中心按「組件目錄」「資料位置」沒反應，提示「沒有成功」。 這兩個按鈕由 WinWidget 用系統的方式打開資料夾（等同在檔案總管裏雙擊）。如果完全沒反應：先確認路徑存在（按鈕會自動建立目錄），再看 %LocalAppData%\WinWidget\logs\app.log 裏那一行錯誤。舊版本把資料夾當成網址開啟，所以一定會失敗，更新到最新版即可。

「檢查更新」說沒有更新通道 / 檢查不到。 config.json 的 update_url 留空時，預設讀本專案 GitHub Releases 的最新版本（api.github.com）。要換成自己的通道，就在 update_url 填一個 JSON 位址，內容是 {"version": "1.2.0", "url": "下載位址", "size": 文件大小, "notes": "更新說明", "page": "介紹頁"}。檢查和下載都在背景執行，不會讓介面卡住；開發者模式不允許自我更新。

媒體組件裏「顯示是哪個程式在播放」關掉還有字。 那是組件頁面自己的顯示邏輯，最新版已修好。若還留着，確認組件資料夾裏的 style.css 是最新的（body.no-app .app { display: none }）。

WinWidget Widget Guide

A widget is a folder: a widget.json file plus ordinary HTML, CSS and JavaScript. If you can build a web page, you can build a widget.

Your first widget in ten minutes

We'll make a "Daily quote" widget: one quote a day, a button for the next one, and quotes you can edit in the Control Center.

1. Create the widget (1 minute)

  • Click the tray icon to open the Control Center.
  • On the Control Center's Add widgets page, press New widget… at the top right (just a "+" when the window is narrow). Or right-click the tray icon → Add widget → New widget….
  • Type the name Daily Quote and press Create.

WinWidget then:

  • creates a folder in your widgets folder (for example %AppData%\WinWidget\widgets\daily-quote) with a working template in it;
  • adds the widget to the desktop;
  • turns on developer mode: from now on, saving a file in that folder reloads the widget on the desktop;
  • opens the folder in File Explorer.

Open the folder in your editor. VS Code is a good choice: thanks to the widget.d.ts file in the folder, it lists everything widget. offers as you type.

2. Add a setting (1 minute)

Open widget.json and replace the whole settings part with:

"settings": [
  { "key": "quotes", "type": "textarea", "label": "Quotes (one per line)",
    "default": "Slow is smooth, smooth is fast.\nEat a proper lunch today.\nDone beats perfect." }
]

Save. In the Control Center, open My widgets, pick "Daily Quote" and its Content tab: there's a text box with the three quotes. WinWidget builds that form from settings on its own.

3. Build the page (3 minutes)

Replace index.html with:

<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="w-label" id="day"></div>
  <p class="quote" id="quote"></p>
  <button class="w-btn" id="next">Next</button>
  <script src="main.js"></script>
</body>
</html>

Replace style.css with:

body {
  display: flex;
  flex-direction: column;
  gap: 8px;
}

.quote {
  flex: 1;
  margin: 0;
  font-size: 1.3rem;
  line-height: 1.5;
}

#next {
  align-self: flex-end;
}

<body> is the card itself. w-label and w-btn come with WinWidget; the theme supplies the background, corners, fonts and colors, so you don't write any of that.

4. Add the logic (3 minutes)

Replace main.js with:

const $ = (id) => document.getElementById(id);
let quotes = [];
let index = 0;

function show() {
  const quote = quotes.length ? quotes[index % quotes.length] : "Add quotes in the Control Center";
  $("quote").textContent = quote;
  $("day").textContent = new Date().toLocaleDateString(widget.locale, {
    month: "long", day: "numeric", weekday: "long",
  });
}

// Read the setting: one quote per line
function load(settings) {
  quotes = settings.quotes.split("\n").map((s) => s.trim()).filter(Boolean);
  show();
}

// A new quote every day; if "Next" was pressed today, remember where it got to
const today = new Date().toDateString();
widget.storage.get("pick").then((pick) => {
  const dayNumber = Math.floor(Date.now() / 86400000);
  index = pick && pick.day === today ? pick.index : dayNumber;
  load(widget.settings.get());
});

// The quotes changed in the Control Center: show them right away
widget.settings.onChange(load);

$("next").addEventListener("click", () => {
  index++;
  widget.storage.set("pick", { day: today, index });
  show();
});

Save, and the widget on the desktop changes at once. Try:

  • pressing Next;
  • editing the quotes in the Control Center: the desktop updates as you type;
  • switching to another theme under Themes: fonts and colors follow;
  • restarting WinWidget: today's quote is still the one you picked (widget.storage keeps it).

5. When something breaks (1 minute)

In developer mode, a script error shows as a red bar at the bottom of the card with the message and where it happened (for example main.js:12). Click the bar to open the developer tools, or press F12 on the widget. Fix it, save, and the bar goes away.

6. Share it (1 minute)

Control Center → Add widgets → your widget's card → Export .fwz. Anyone can install it by double-clicking the .fwz file (or dropping it on the Control Center window).

To let everyone find it under Online in the Control Center, submit it to the widget market: put the widget folder in widgets/<your-github-name>.<widget>/ of the fullwidget-market repository on GitHub and open a pull request. Once the automatic check passes and a maintainer has looked at it, it goes live; CONTRIBUTING.md there has the details.

JavaScript API

WinWidget sets up the global widget before your script runs: nothing to import. Full types and notes are in widget.d.ts.

Anything that waits (saved data, network…) returns a Promise, so you can await it.

Now playing: widget.media (needs media)

Reads what's playing in Windows' media controls (Spotify, browsers, the Media Player app… the same as the volume flyout shows) and controls it:

widget.media.onChange((m) => {
  if (!m.available) return;          // nothing is playing
  // m.title, m.artist, m.album, m.app.name ("Spotify"), m.app.icon
  // m.playing, m.position, m.duration (ms), m.cover (the album art's address, ready for an <img>)
  // m.can.next, m.can.previous, m.can.seek: which buttons the app accepts right now
});
const now = widget.media.position(m);   // where playback is now (it moves on while playing)
await widget.media.toggle();            // play / pause; also play(), pause(), next(), previous()
await widget.media.seek(60000);         // jump to 1:00
// timed lyrics of the current song, looked up on NetEase Cloud Music, QQ Music and Kugou
const { title, lyrics } = await widget.media.lyrics();
if (lyrics.found) lyrics.lines;         // [{ t: ms, text, tr?: translation }], in order

Windows reports every change at once (a new track, pause, another app starting to play), so there is nothing to poll.

A folder the user chose: widget.files

Add a setting of type folder. Once the user picks a folder, the widget can read the pictures in it. Choosing the folder is the permission: nothing goes in permissions.

{ "key": "folder", "type": "folder", "label": "Photo folder", "default": "%USERPROFILE%\\Pictures" }
const { files } = await widget.files.list("folder", { recursive: true });
// files: [{ path: "2025/beach.jpg", name: "beach", size, modified, url }]
img.src = widget.files.url(files[0], { width: 800 });   // a smaller copy made by Windows: fast, and light on memory
const { taken } = await widget.files.info("folder", files[0]);  // when the camera took it, or null
await widget.files.pick("folder");      // opens the folder dialog from the widget and saves the choice
  • Only pictures in that folder (and its subfolders): jpg, png, gif, webp, bmp, avif, heic, tif; up to 5000.
  • For someone else's widget, the folder in default doesn't count: it can read only after the user has picked one. Built-in widgets and your own can use the default.
  • Folder values may contain environment variables such as %USERPROFILE%.

Network: widget.fetch (needs network: permissions)

Like the browser's fetch, but sent by WinWidget, so CORS doesn't apply:

const r = await widget.fetch(
  "https://api.open-meteo.com/v1/forecast?latitude=25&longitude=121&current=temperature_2m"
);
if (r.ok) {
  const data = await r.json();
}

await widget.fetch("https://example.com/api", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: { hello: "world" },   // objects are sent as JSON
});

The response has ok, status, statusText, url, headers, body (text), text() and json(). For binary content such as images pass { as: "base64" } and body holds base64 text. Up to 8 MB per response; redirects are followed, and every hop must be allowed.

// Opens in the default browser; mailto: works too

A widget page can't navigate away or open windows itself; use this to open web pages.

From being loaded to being removed, a card gets its events in a fixed order. Subscribe to all of them with widget.on(name, callback); the return value unsubscribes.

Ordering guarantees

  • ready always comes before the first show. Put one-time startup work in ready and show cannot cut in front of it.
  • A card that is already on screen (the default at launch) gets show{ initial: true } right after ready; one that starts hidden (hide-all is on) gets nothing until it is really shown.
  • show and hide come in pairs, and the same state is never repeated: hide after hide is not sent twice, nor is show after show. widget.visible always tells you where you are.
  • hide arrives while the card is still alive; unload means this time it is really leaving. Do-once work (save, clear timers) belongs in unload; pausing animation belongs in hide.
// Cheap while running: stop when invisible, recompute when back
let timer = 0;
function start() {
  if (timer || !widget.visible) return;
  timer = setInterval(tick, 1000);
  tick();
}
function stop() {
  clearInterval(timer);
  timer = 0;
}

widget.on("ready", () => start());
widget.on("show", ({ from, initial }) => {
  widget.log("shown", from, initial);   // from, see the table above
  start();
});
widget.on("hide", () => stop());
widget.on("unload", ({ kill }) => {
  stop();
  if (kill) widget.storage.set("lastSeen", Date.now());
});

// Re-layout when the size changes (no need for window resize: that is the window, with DPI math)
widget.on("resize", ({ width }) => {
  document.body.dataset.compact = width < 260 ? "1" : "";
});

widget.visible is the current state, kept in step by show / hide. A card deliberately never takes the keyboard focus, so there is no focus / blur event: a widget that needs typing puts an input in its own page, and the user clicks it.

Looks: follow the theme

WinWidget comes with several themes, and users can adjust background, text color, accent color, font, text size, corners, padding and opacity in the Control Center. Use the variables and classes below and all of that just works for your widget.

Layout

  • <body> is the card: background, corners, border and padding are already set. Put your content straight into <body>.
  • <html> is the transparent window with room for the shadow around the card; don't give it a background.
  • Size text in rem: when users change the text size, 1rem follows (14px by default).
  • Cards can be resized. Lay out with flex or grid; to adapt to size, set container-type: size on body and use @container (max-height: 100px) { … }. @container rules style what is inside body, not body itself.

Content that grows with the card

Add "grow": 1 to size in widget.json, and when the user makes the card bigger than its default size, the whole content is magnified with it (text, icons and spacing alike) instead of leaving empty space:

"size": { "width": 260, "height": 150, "minWidth": 180, "minHeight": 110, "grow": 1 }
  • The factor is the smaller of "how many times wider" and "how many times taller", at most 3. At twice the width and 1.3 times the height the content grows 1.3 times, and your layout gets the extra width.
  • Below the default size nothing shrinks: small sizes are up to your layout (@container, above).
  • grow may be anything from 0 to 1: for lists, 0.5 makes the text a little bigger while showing more items.
  • Leave it out (or 0) to keep the old behaviour: more room, same size.
  • The card's corners, outline and shadow don't grow. The current factor is in the CSS variable --w-size-scale.

Saving power: don't animate what updates every second

Widgets stay open all day, and every frame drawn costs something. A figure or bar that updates every second with a 0.5-second transition is animating nearly all the time: one widget can use 20% of a CPU core that way, against 1% without.

  • No transition or animation on anything that updates every second or faster. w-bar animates its width for 0.5 s by default; for bars updated every second add .w-bar > i { transition: none; }.
  • No animation: … infinite; to blink for attention, give a count (such as 8).
  • Hands, dials and anything else that turns: put it on its own element and turn it with a CSS transform, rather than redrawing a whole SVG every second.
  • What changes once a minute, update once a minute (setTimeout to the next minute).

Dragging, menus and clicks

WinWidget handles these for you:

  • Dragging: press anywhere on the card and drag to move the widget. Buttons, links and inputs don't start a drag; add data-no-drag to anything else that shouldn't.
  • Right-click shows the WinWidget widget menu. Add data-no-menu where you want to handle right-clicks yourself.
  • Resizing: unless size.resizable is false, there's a grip in the bottom-right corner.
  • Locking: a locked widget can't be moved or resized; check widget.locked or html[data-locked].

Packaging and sharing

A .fwz file is a widget folder zipped up with another extension.

  • Export: Control Center → Add widgets → your widget's card → Export .fwz. Hidden files and folders (such as .git) and node_modules are left out.
  • Install: double-click a .fwz file, drop it on the Control Center window, or press Install .fwz file… under Add widgets. The name, author, version and permissions are shown before anything is installed.
  • Update: raise version and export again. A widget with the same id is replaced; copies on the desktop keep their settings and saved data, and the old version goes to the Recycle Bin.
  • Frameworks: React, Vue, Svelte and others all work, as long as the output is static files. Put the build output (e.g. dist/) next to widget.json, point entry at its index.html, and use relative asset paths (with Vite, base: "./").

WinWidget has no key for it, so dropping a .upxs gets an explicit answer instead of a fake success:

The changelog says it plainly: "安装包格式升级为 UPXS 格式。这一格式不仅具有加密功能，还包含开发者信息签名". Measured on that 1.6 MB file: apart from the first four bytes (c8 01 00 00) every block scores 8.0 entropy, with no zip, gzip or JSON signature anywhere — and no repeating-key structure either, so it is not a simple XOR.

The workable route is to install it in uTools first, then move the installed copy over. uTools keeps unpacked plugins in %APPDATA%\uTools\plugins\, one .asar per plugin — an Electron archive, not encrypted. WinWidget reads those directly:

  • Install the plugin in uTools as usual.
  • Find the matching <hash>.asar in %APPDATA%\uTools\plugins\ (if unsure which one, try them through the import button; the confirm dialog shows the plugin name).
  • Control Center → Add widgets → Install .fwz / .upx… and pick it, or simply drop the .asar on the Control Center.

The .asar header is [u32 4][u32 pickle][…][u32 jsonLen], its payload starts at 8 + pickle, and directory entries are {size, offset:"…", unpacked?, link?} — the same layout as .upx with a different header, so both share one "unpack → build widget.json from plugin.json" flow. Entries marked unpacked (native modules and the like) are read from the sibling <name>.asar.unpacked\ folder.

Also worth knowing: utools.getAppVersion() reports a compatibility level (currently 7.6.0), not WinWidget's own version. Plugins routinely write parseFloat(utools.getAppVersion()) < 7 to decide whether the host is new enough; answering 1.0.0 makes them paint an "uTools is too old" page over everything.

The host-side names are clipboard.history / .stats / .pin / .remove / .clear / clipboard.recopy / clipboard.image / clipboard.filesExist, all behind the clipboard permission.

"Paste" needs no new API: utools.hideMainWindowPasteText/File/Image already does hide → restore the previous window → Ctrl+V, so copy followed by one of those pastes whatever you put there.

How pictures land: when a screenshot arrives, the host writes the PNG to data\clipboard\images\<hash>.png and records its path in value with the byte count in size. uTools plugins load it through utools.db.getAttachment("attachment/" + hash), so the first time a page reads such a record services.js posts the bytes into that widget's own attachment store under attachment/<hash> and rewrites value to that id — thumbnails and the favourite flow then share one path.

Favourites work two ways: the plugin keeps its own collect/<hash> documents and lists them with utools.db.promises.allDocs("collect/"), while the host record carries a pinned flag (clipboard.history.pin). To make the former work, utools.js now accepts a prefix string in db.allDocs (it used to take only {idStartsWith}), db.getAttachment returns an object that also has buffer / byteLength / length (uTools hands back a Node Buffer, and plugins write new Blob([n.buffer])), and db.postAttachment takes an ArrayBuffer or a TypedArray.

Where uTools plugins stand (how far compatibility goes)

A uTools plugin is an Electron app: plugin.json, a preload.js that runs with Node (require("fs"), Sharp and FFmpeg installed there), and a page. WinWidget is Rust + WebView2 — no Electron, no Node — so a uTools plugin cannot be dropped in unchanged. What can be carried over is the page plus the utools.* calls it makes: every widget page gets a utools compatibility layer (/__fw/utools.js) wired to WinWidget's own capabilities.

Bringing an existing uTools plugin's screen in

  • Put the plugin's index.html, CSS and JS into a widget folder;
  • declare the permissions it actually uses in widget.json (showNotification → notify, copyText → clipboard, captureScreen → screen, shellOpenPath → shell.launch, shellOpenExternal → shell.open);
  • the utools.* calls are answered by the compatibility layer, no code changes needed.

Don't expect preload.js, require(...), process, fs or child_process: they do not exist here, and a copied preload just leaves the page blank. ipcRenderer is present as a page-side stand-in (see "Windows of your own") — it carries this widget's window messages, not Electron's process-to-process traffic.

How a widget talks to the host (advanced)

Everything above is enough to build a complete widget. This chapter is for people who want to know how it actually runs: where the page comes from, what the host hands it, which messages exist, and where the data lives.

How the page is opened

WinWidget does not open your index.html from file://. It runs a small HTTP server bound to 127.0.0.1 and serves the page:

http://127.0.0.1:<port>/__fw/<widget id>/index.html
  • The port changes on every start, so always use relative paths (style.css, main.js, img/a.png) — never a hard-coded 127.0.0.1:8800.
  • Each widget type has its own origin, <widget id>.widgets.localhost, so localStorage, IndexedDB and Cache are separated per widget type, shared by all its instances.
  • The page cannot navigate elsewhere or open a new window; use widget.shell.open for web pages.
  • Images, fonts and scripts the page loads are bound by the same network: permissions.

1. A number from a web API on the desktop

Show a GitHub project's star count, refresh every 30 minutes, and keep the last value when the network fails.

widget.json: "permissions": ["network:api.github.com"].

const $ = (id) => document.getElementById(id);
const KEY = "last";

async function fetchOnce() {
  const r = await widget.fetch("https://api.github.com/repos/Demon1110/WinWidget", {
    headers: { accept: "application/vnd.github+json" },
  });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const repo = await r.json();
  return { stars: repo.stargazers_count, at: Date.now() };
}

async function refresh() {
  try {
    const data = await fetchOnce();
    show(data, false);
    await widget.storage.set(KEY, data);
  } catch (e) {
    // Fall back to the last good value and mark it as stale.
    const old = await widget.storage.get(KEY);
    if (old) show(old, true);
    else $("stars").textContent = "—";
    widget.log(`stars: ${e.message}`);
  }
}

function show(data, stale) {
  $("stars").textContent = data.stars.toLocaleString(widget.locale);
  $("at").textContent = new Date(data.at).toLocaleTimeString(widget.locale, { hour: "2-digit", minute: "2-digit" });
  $("stale").hidden = !stale;
}

refresh();
setInterval(refresh, 30 * 60 * 1000);
document.addEventListener("visibilitychange", () => { if (!document.hidden) refresh(); });
  • permissions needs network:api.github.com, not *.github.com: ask for as little as possible.
  • Something to show even before (or without) data, so the card is never blank.
  • setInterval is fine; never poll per second what has an event (widget.media, widget.audio).

  cell.style.height = `${Math.max(4, Math.min(100, value))}%`;
  bar.appendChild(cell);
  if (bar.children.length > 20) bar.firstElementChild.remove();
}
#cpu, #mem { font-variant-numeric: tabular-nums; }   /* digits stop jittering */
.mini { display: flex; align-items: flex-end; gap: 1px; height: 1.6rem; }
.mini i { width: 2px; background: var(--w-accent); } /* no transition, no animation */
  • No transition or animation on anything that changes every second: a 0.5 s animation means the card repaints constantly.
  • tabular-nums keeps numbers from shifting sideways.
  • Unsubscribe when you no longer need it (const stop = widget.system.subscribe(...); stop();).

3. Two copies of the same widget, separate data

// The card is dragged and resized, but the instance id never changes: use it to separate data.
const key = `state:${widget.instanceId}`;

const saved = await widget.storage.get(key);
index = saved ? saved.index : 0;

function save() {
  widget.storage.set(key, { index });   // no await needed, writes are quick
}

widget.storage is per widget type (both copies share one file), so put instanceId in the key when they must not share; settings are per instance already.

Checklist before you hand a widget out

  • id uses only lowercase letters, digits and . _ -, 2–64 characters, and never changes afterwards.
  • entry exists, and every resource is a relative path.
  • Files are UTF-8 (a BOM will break widget.json parsing).
  • Everything you use is declared in permissions; prefer network:some.site over network:*.
  • Something is visible on first paint; when data fails, say so in plain words instead of leaving the card blank.
  • Nothing that updates every second has an animation; nothing that has an event is polled.
  • Numbers and dates go through widget.locale; words go through widget.t().
  • Only --w-* variables and w-* classes, checked on all three themes.
  • It survives being resized: flex/grid, @container where needed, grow if the content should scale.
  • No window.open, no navigation, no document.write; use widget.shell.open.
  • No CDN scripts or fonts (they break offline) — bundle them in the widget folder.
  • Look at the Console with F12 in developer mode before exporting the .fwz.

Questions

I changed a file and nothing happened on the desktop. Check that developer mode is on under Settings. If it's off, right-click the widget → Reload. If you changed widget.json and the widget disappeared, look at the top of Add widgets for an error.

**widget.fetch fails with "permission denied".** Add the site to permissions, e.g. "network:api.example.com"; the error message names the exact line to add. If it says "not allowed yet", the permission is declared but the user hasn't allowed it: pick the widget under My widgets and press Review.

**A plain fetch() or <img> from the web doesn't load.** The site has to be in permissions. A plain fetch() also needs the site to allow CORS; if it doesn't, use widget.fetch.

Text shows up garbled. Save the files as UTF-8.

I want the widget bigger or smaller when it's first added. Change size.width and size.height. Copies already on the desktop keep the size the user gave them; add a new one from Add widgets to see the change.

How do I make it look right on the light Paper theme? Use the --w-* variables for text and lines instead of hard-coded white or black, and check all three themes under Themes.

I changed the language and the widget still speaks the old one. The language is read from config.json at startup, so restart WinWidget; the control center itself follows immediately, cards already open reload on the next launch.
