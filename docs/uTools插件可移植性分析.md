# uTools 插件可移植性分析

对象：`C:\Users\admin\Desktop\新建文件夹` 下 57 个 `.asar` 包。
判定口径只有一个问题：**在现有 WinWidget SDK 与 Hub 投稿规范内，能不能做成一个组件**。

## 一、结论速览

| 分类 | 含义 | 数量 |
| --- | --- | --- |
| A · 能力已全覆盖 | 纯页面逻辑，宿主 API 够用，重写就能上架 | 10 |
| B · 缺静态数据 | 逻辑简单，但依赖字体、节假日表、色卡、美术资源 | 8 |
| C · 缺宿主能力 | 卡在具体 API：全局输入、顶层幕布、AI、OCR、文件读写、视频编码、特权命令、TCP | 30 |
| D · 不建议移植 | 依赖作者云服务、付费校验，或体量远超组件形态 | 9 |
| 合计 | | 57 |

这批都是**第三方作者**的插件（plugin.json 里带 author，如 Surpass Studio、xiaou、pony_ma）。公开仓库直接照搬源码和美术资源有再分发风险，所以本次落地一律**按功能自研重写**，不复制原包里的代码、图片、字体。

## 二、包格式

这批文件不是标准 Electron asar：头部是 `uint32 4` + 三个 size 字段，JSON 目录从偏移 16 开始，payload 相对 JSON 头末尾按 4 字节对齐。标准 asar 读取（读 offset 8 起 JSON）在这里全部失败，必须用 `raw_decode` 从 `{"files"` 扫到 JSON 结尾，再用 `.json` 条目回读校验 payload base。

56/57 解包成功。「古诗和成语」（`0f0600b6…`，16MB）的 payload base 无法定位，直接读字节确认是 pluginName 古诗和成语 / v1.0.5 / 作者 wdd，内容为古诗与成语词条。

## 四、C 类拆成能力缺口

| 缺口 | 涉及插件数 | 需要的 API |
| --- | --- | --- |
| 全局键鼠监听 | 4 | `input.subscribe(["key","mouse"], cb)`，宿主侧低级钩子；`input` 权限位已存在 |
| 顶层穿透幕布 / 多屏浮窗 | 9 | 顶层维持、DWM `DWMWA_EXCLUDED_FROM_PEEK`、空闲降耗（你已明确否掉，本次不动） |
| 本地文件读写 | 5 | `file.read(path)` / `file.write(path, bytes)`；现在只有 pick / save 对话框 |
| 视频编码 / 录屏 | 3 | 连续帧采集 + 编码；`视频批量处理` 走 ffmpeg 可解 |
| OCR / PDF | 2 | `ocr.run` / `pdf.render`，成本最高，建议不做 |
| AI | 3 | `ai.chat` / `ai.models` |
| 特权系统命令 | 4 | 白名单 `system.exec`，读注册表与进程列表 |
| 局域网监听 | 1 | `net.serve` |
| 3D / 全屏特效窗 | 2 | 与顶层幕布同源 |

排序建议（按一次投入解锁的数量）：`input.subscribe` > ffmpeg 官方工具包 > `net.serve` > `system.exec` > `ai.chat`。文件读写看起来最基础，但它是 5 个插件的共同门槛，实际优先级应排在 `input.subscribe` 之后、`system.exec` 之前。
