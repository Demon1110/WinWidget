## 十分钟写第一个组件

我们来做一个“每日一句”：每天显示一句话，按一下换下一句，句子可以在控制中心改。

### 1. 建立组件（1 分钟）

1. 左键点托盘图标，打开控制中心。
2. 到控制中心“添加组件”页，按右上角的 **新建组件…**（窗口窄时只显示“＋”图标）。也可以右键系统托盘图标 →“添加组件”→“新建组件…”。
3. 名称输入 `每日一句`，按 **建立**。

WinWidget 会：

- 在组件目录建立一个文件夹（例如 `%AppData%\WinWidget\widgets\my-widget`），里面是一个能用的模板；
- 把它放到桌面；
- 打开 **开发者模式**：之后改了文件夹里的文件，一保存，桌面上的组件就会自动重新加载；
- 用资源管理器打开这个文件夹。

用你习惯的编辑器打开这个文件夹。推荐 [VS Code](https://code.visualstudio.com/)：文件夹里的 `widget.d.ts` 会让它在你打 `widget.` 时列出所有可用的功能和说明。

### 2. 加一个设置项（1 分钟）

打开 `widget.json`，把 `settings` 整段换成：

```json
"settings": [
  { "key": "quotes", "type": "textarea", "label": "句子（一行一句）",
    "default": "慢慢来，比较快。\n今天也要好好吃饭。\n先完成，再完美。" }
]
```

保存。打开控制中心 →“我的组件”→ 选“每日一句”→“内容”，会看到一个多行文字框，里面是这三句话。这个表单是 WinWidget 照 `settings` 自动生成的。

### 3. 写画面（3 分钟）

把 `index.html` 换成：

```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="w-label" id="day"></div>
  <p class="quote" id="quote"></p>
  <button class="w-btn" id="next">换一句</button>
  <script src="main.js"></script>
</body>
</html>
```

把 `style.css` 换成：

```css
body {
  display: flex;
  flex-direction: column;
  gap: 8px;
}

.quote {
  flex: 1;
  margin: 0;
  font-size: 1.3rem;
  line-height: 1.5;
}

#next {
  align-self: flex-end;
}
```

`<body>` 就是那张卡片。`w-label`、`w-btn` 是 WinWidget 自带的样式，背景、圆角、字体和颜色由主题提供，你不用写。

### 4. 写逻辑（3 分钟）

把 `main.js` 换成：

```js
const $ = (id) => document.getElementById(id);
let quotes = [];
let index = 0;

function show() {
  const quote = quotes.length ? quotes[index % quotes.length] : "到控制中心加几句话吧";
  $("quote").textContent = quote;
  $("day").textContent = new Date().toLocaleDateString(widget.locale, {
    month: "long", day: "numeric", weekday: "long",
  });
}

// 读设置：一行一句
function load(settings) {
  quotes = settings.quotes.split("\n").map((s) => s.trim()).filter(Boolean);
  show();
}

// 每天自动换一句；按过“换一句”的话，记住今天换到哪一句
const today = new Date().toDateString();
widget.storage.get("pick").then((pick) => {
  const dayNumber = Math.floor(Date.now() / 86400000);
  index = pick && pick.day === today ? pick.index : dayNumber;
  load(widget.settings.get());
});

// 用户在控制中心改了句子，马上更新
widget.settings.onChange(load);

$("next").addEventListener("click", () => {
  index++;
  widget.storage.set("pick", { day: today, index });
  show();
});
```

保存，桌面上的组件马上变成新的样子。试试：

- 按“换一句”；
- 在控制中心改句子，桌面上即时更新；
- 到“主题”换一套主题，组件的字体和颜色会跟着变；
- 重新启动 WinWidget，今天换到的那一句还在（`widget.storage` 会一直保存）。

### 5. 出错了怎么办（1 分钟）

开发者模式下，脚本出错时卡片底部会出现一条红色提示，写着错误和位置（例如 `main.js:12`）。点一下它就会打开开发者工具；也可以在组件上按 **F12**。改好保存，提示就会消失。

### 6. 分享出去（1 分钟）

控制中心 →“添加组件”→ 你的组件卡片 →“导出 .fwz”。别人双击这个 `.fwz` 文件就能安装（也可以拖到控制中心窗口上）。

想让所有人都能在控制中心的“线上”里找到它，可以投稿到[组件市场](https://hmgvibe.github.io/fullwidget-market/)：把组件文件夹放进 GitHub 上 [fullwidget-market](https://github.com/hmgvibe/fullwidget-market) 保存库的 `widgets/你的账号.组件名/`，开一个 pull request。自动检查通过、维护者看过后就会上架，详细步骤见那里的 CONTRIBUTING.md。

## 文件夹里有什么

| 文件 | 用途 |
|---|---|
| `widget.json` | 说明文件：名称、尺寸、权限、设置项。**必须有。** |
| `index.html` | 组件的页面（可以在 `widget.json` 的 `entry` 改成别的档名）。 |
| `style.css`、`main.js` | 样式和逻辑。档名随意，在 HTML 里用相对路径引用即可。 |
| `icon.svg` | 在组件库、托盘菜单和控制中心显示的图标（建议 24×24 的 SVG）。 |
| `widget.d.ts`、`jsconfig.json` | 只给编辑器用，让它提示 `widget.` 的写法。 |

组件目录：`%AppData%\WinWidget\widgets\`。在控制中心“设置”→“组件目录”可以直接打开。把一个组件文件夹放进去，它就会出现在“添加组件”里（开发者模式下自动出现，否则按“重新扫描”）。

文件请存成 **UTF-8**。

## widget.json

可以写 `//` 注解，最后一项后面多一个逗号也没关系。

```json
{
  "id": "me.daily-quote",
  "name": { "zh-TW": "每日一句", "zh-CN": "每日一句", "en": "Daily Quote" },
  "description": "每天一句话",
  "version": "1.0.0",
  "author": "你的名字",
  "entry": "index.html",
  "icon": "icon.svg",
  "category": "info",
  "size": {
    "width": 280, "height": 160,
    "minWidth": 200, "minHeight": 120, "maxWidth": 600, "maxHeight": 400,
    "resizable": true
  },
  "layer": "desktop",
  "permissions": [],
  "settings": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识。小写英文、数字和 `. _ -`，2–64 个字元，例如 `me.daily-quote`。之后不要改：保存的数据和更新都靠它。`winwidget.` 开头的留给内建组件。 |
| `name` | 建议 | 显示的名称。可以是文字，也可以按语言给：`{ "zh-TW": "…", "en": "…" }`。 |
| `description` | | 一句话介绍，显示在组件库。同样可以按语言给。 |
| `version` | 建议 | 版本号，例如 `1.2.0`。安装 `.fwz` 时用它判断是更新、重新安装还是旧版本。 |
| `author` | | 作者。 |
| `entry` | | 页面档，默认 `index.html`。 |
| `icon` | | 图标档。没有的话显示名称的第一个字。 |
| `category` | | 在组件库里放在哪一类：`time`（时间）、`weather`（天气）、`system`（系统）、`productivity`（效率）、`info`（信息）、`media`（媒体与装饰）。不写或写别的，放在“其他”。 |
| `preview` | | 组件库卡片上的预览图，例如 `"preview.png"`。可以按主题和语言各放一张：`"preview/{theme}.{lang}.webp"`，`{theme}` 换成主题 id（`instrument`、`type`、`paper`），`{lang}` 换成 `zh-TW`、`zh-CN` 或 `en`；缺的那张会用同主题的其他语言，或其他主题代替。图片建议用透明背景的 PNG 或 WebP，宽 300 像素左右。没有的话卡片显示图标。 |
| `size` | | 卡片尺寸（不含阴影），单位是像素。`width`/`height` 是第一次放上桌面的大小；`min*`/`max*` 限制用户拖动缩放的范围；`resizable: false` 不让缩放；`grow`（0–1）决定用户把卡片拉得比默认大时，内容要不要跟着放大，见[放大时内容跟着变大](#放大时内容跟着变大)。 |
| `layer` | | 第一次放上桌面时的层级：`desktop`（默认，在所有窗口下面，Win+D 也看得到）、`normal`、`top`（置顶）。用户之后可以改。 |
| `permissions` | | 要用到的权限，见[权限](#权限)。 |
| `settings` | | 设置项。控制中心会照这里自动生成表单。 |

### settings：设置项

每一项：

```json
{
  "key": "city",
  "type": "text",
  "label": "城市",
  "description": "留空就自动定位",
  "default": ""
}
```

| 字段 | 说明 |
|---|---|
| `key` | 程序里用的名字：`widget.settings.get("city")`。 |
| `type` | 见下表。 |
| `label` | 表单上的名称。可以按语言给。 |
| `description` | 名称下面的一行小字说明。 |
| `default` | 默认值。任何类型都可以按语言给，例如 `{ "zh-TW": "google", "zh-CN": "baidu", "en": "google" }`。 |
| `placeholder` | 输入框里的提示文字。 |
| `min` `max` `step` | `number` 和 `slider` 用。 |
| `options` | `select` 用：`[{ "value": "c", "label": "摄氏" }, { "value": "f", "label": "华氏" }]`。 |

| type | 表单 | 值 |
|---|---|---|
| `toggle` | 开关 | `true` / `false` |
| `text` | 单行文字 | 字串 |
| `textarea` | 多行文字 | 字串（换行是 `\n`） |
| `number` | 数字框 | 数字 |
| `slider` | 滑块 | 数字 |
| `select` | 下拉菜单（三个以内的短选项会显示成分段按钮） | 选项的 `value` |
| `color` | 颜色 | `"#rrggbb"` |
| `font` | 字体（可从系统字体中选） | 字体名称；用户清空时是 `null`（通常就用主题的字体） |
| `date` | 日期 | `"2026-12-31"` |
| `folder` | 文件夹（显示路径和“选择…”按钮） | 完整路径；默认值可以写环境变数，例如 `"%USERPROFILE%\\Pictures"`。见 [`widget.files`](#读取用户选的文件夹widgetfiles) |

## JavaScript API

WinWidget 会在你的脚本执行前准备好全局的 `widget`，不用 import。完整的型别和说明在 `widget.d.ts`。

需要等待的功能（读写数据、连网等）都回传 Promise，可以用 `await`。

### 基本数据

```js
widget.id          // "me.daily-quote"
widget.instanceId  // 桌面上这一个的标识（同一个组件可以放几个）
widget.locale      // 用户的语言，例如 "zh-TW"，格式化日期和数字用
widget.theme       // 目前的主题："instrument"、"type"、"paper"
widget.developer   // 是否在开发者模式
widget.permissions // 现在能用的权限

// 按用户的语言挑文字
widget.t({ "zh-TW": "早安", "zh-CN": "早安", en: "Good morning" })
```

### 设置：`widget.settings`

```js
// 读设置：同步的，不用 await
const all = widget.settings.get();         // { quotes: "…", … }
const one = widget.settings.get("quotes");

// 用户在控制中心改了设置
widget.settings.onChange((all) => { /* … */ });

// 程序也可以改，控制中心会同步显示
await widget.settings.set("quotes", "…");
```

### 保存数据：`widget.storage`

保存的东西重开电脑也在；用户移除这个组件时一起删除。桌面上每一个组件各有自己的一份。上限每个 2 MB。

```js
// 可以存任何 JSON 数据
await widget.storage.set("todo", [{ text: "买牛奶", done: false }]);

// 没存过的是 null
const todo = (await widget.storage.get("todo")) || [];

await widget.storage.remove("todo");
const keys = await widget.storage.keys();
```

### 系统信息：`widget.system`（需要 `system` 权限）

```js
const stop = widget.system.subscribe(["cpu", "memory"], (d) => {
  cpu.textContent = Math.round(d.cpu.usage) + "%";
  mem.textContent = Math.round(d.memory.usage) + "%";
}, { interval: 2000 });  // 每 2 秒一次，默认 1 秒；第一笔会马上到

stop(); // 不需要时停止
```

| 主题 | 内容 |
|---|---|
| `cpu` | `usage`（%）、`cores` |
| `memory` | `usage`（%）、`total`、`used`、`available`（字节） |
| `network` | `down`、`up`（每秒字节）、`totalDown`、`totalUp` |
| `disk` | 每个磁盘一项（含随身碟）：`name`（"C:"）、`label`、`type`（`fixed` / `removable`）、`total`、`free`、`usage`（%） |
| `battery` | `present`、`percent`、`charging`、`pluggedIn`、`secondsLeft`、`saver`（省电模式） |

多个组件订阅同一个数据时，WinWidget 只取样一次，不会多耗资源。

不常变的数据用一次性的呼叫：

```js
const pc = await widget.system.info();
// pc.os.name "Windows 11 Pro"、pc.os.version "25H2"、pc.cpu.name、pc.memory.installed（字节）、
// pc.gpus（显卡名称）、pc.computer（电脑名称）、pc.uptime（已开机的毫秒数）

const net = await widget.system.adapters();
// net.online；net.adapters[0] 是连上网络的那个：name "Wi-Fi"、type "wifi"、ipv4、gateways、dns

const r = await widget.system.ping("1.1.1.1");   // { ok, ms, status }；每个组件每秒最多一次
```

### 音量：`widget.audio`（需要 `audio` 权限）

```js
const stop = widget.audio.onChange((a) => {
  // a.volume 0–100、a.muted、a.device（"喇叭 (Realtek Audio)"）
  // 按键盘的音量键、工作列调音量、换成耳机时都会马上通知
});
await widget.audio.set({ volume: 40 });
await widget.audio.set({ muted: true });
```

### 正在播放：`widget.media`（需要 `media` 权限）

读取 Windows 媒体控制里正在播放的内容（Spotify、浏览器、媒体播放器……，和音量面板上看到的一样），并控制它：

```js
widget.media.onChange((m) => {
  if (!m.available) return;          // 没有程序在播放
  // m.title、m.artist、m.album、m.app.name（"Spotify"）、m.app.icon
  // m.playing、m.position、m.duration（毫秒）、m.cover（封面图片的网址，可直接放进 <img>）
  // m.can.next、m.can.previous、m.can.seek：那个程序现在接受哪些按钮
});
const now = widget.media.position(m);   // 现在播到哪里（播放中会自己往前走）
await widget.media.toggle();            // 播放 / 暂停；也有 play()、pause()、next()、previous()
await widget.media.seek(60000);         // 跳到 1:00
// 目前这首歌的时间轴歌词，在网易云音乐、QQ 音乐、酷狗上查找
const { title, lyrics } = await widget.media.lyrics();
if (lyrics.found) lyrics.lines;         // [{ t: 毫秒, text, tr?: 翻译 }]，按时间排好
```

Windows 有变化时会马上通知（换歌、暂停、换了一个程序在播放），不用自己轮询。

### 读取用户选的文件夹：`widget.files`

在设置项里放一个 `folder` 类型的设置，用户选了文件夹，组件就能读取里面的图片。**选文件夹本身就是允许**，不用在 `permissions` 声明：

```json
{ "key": "folder", "type": "folder", "label": "照片文件夹", "default": "%USERPROFILE%\\Pictures" }
```

```js
const { files } = await widget.files.list("folder", { recursive: true });
// files: [{ path: "2025/海边.jpg", name: "海边", size, modified, url }]
img.src = widget.files.url(files[0], { width: 800 });   // Windows 做的缩小版，大照片也很快、很省内存
const { taken } = await widget.files.info("folder", files[0]);  // 拍摄时间（相机记录的），没有时是 null
await widget.files.pick("folder");      // 在组件里直接打开选文件夹的窗口，选好后存进设置
```

- 只能读那个文件夹（和里面的子文件夹）里的图片：jpg、png、gif、webp、bmp、avif、heic、tif，最多 5000 张。
- 别人写的组件，`default` 里写的文件夹不算数，要等用户自己选过才能读。内建组件和自己写的组件可以用默认值。
- 文件夹的设置值里可以写环境变数，例如 `%USERPROFILE%`。

### 连网：`widget.fetch`（需要 `network:` 权限）

和浏览器的 `fetch` 很像，但由 WinWidget 代为发送，所以不受 CORS 限制：

```js
const r = await widget.fetch(
  "https://api.open-meteo.com/v1/forecast?latitude=25&longitude=121&current=temperature_2m"
);
if (r.ok) {
  const data = await r.json();
}

await widget.fetch("https://example.com/api", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: { hello: "world" },   // 物件会自动转成 JSON
});
```

回应有 `ok`、`status`、`statusText`、`url`、`headers`、`body`（文字）、`text()`、`json()`。图片等二进制内容用 `{ as: "base64" }`，`body` 就是 base64 文字。每次最多 8 MB，会自动跟随转址（每一跳都要在权限内）。

### 打开网址：`widget.shell.open`（需要 `shell.open` 权限）

```js
// 用默认浏览器打开；也接受 mailto:
widget.shell.open("https://example.com");
```

组件页面本身不能跳转到别的网址，也不能开新窗口；要打开网页请用这个。

### 打开程序和文件：`widget.shell.launch`（需要 `shell.launch` 权限）

```js
await widget.shell.launch("C:\\Windows\\notepad.exe");    // 程序、捷径、文件夹、文件都可以；不能带参数

const path = await widget.shell.pick({ type: "file", filter: "programs" }); // 让用户选；取消时是 null
const info = await widget.shell.info(path);  // { name: "记事本", kind: "app", icon: "data:image/png;…" }

// 文件拖到组件上时取得完整路径
document.addEventListener("dragover", (e) => e.preventDefault());
document.addEventListener("drop", async (e) => {
  e.preventDefault();
  const paths = await widget.shell.paths(e.dataTransfer.files);
});
```

`pick` 的 `type` 可以是 `file` 或 `folder`，`filter` 可以是 `programs`、`images` 或 `all`。

### 简繁转换：`widget.convertChinese`

```js
await widget.convertChinese("北极熊和幼崽", "traditional");  // "北极熊和幼崽"
```

用 Windows 内建的字表逐字转换，适合短句（例如网上取得的简体标题），不处理“软件 / 软件”这类用词差异。不需要权限。

### 通知：`widget.notify`（需要 `notify` 权限）

```js
// 马上弹出一则 Windows 通知（标题默认是组件名称）
widget.notify("下载完成");

// 预约在某个时间；同一个 tag 的新预约会取代旧的
widget.notify({ title: "番茄钟", body: "休息一下", at: Date.now() + 25 * 60 * 1000, tag: "end" });

widget.notify.cancel("end"); // 取消这个预约；不给 tag 就取消这个组件的全部预约
```

预约由 WinWidget 计时，所以就算组件因为全屏幕或“隐藏全部组件”暂停了，通知也会准时出现。最多预约 7 天以内、每个组件 20 则；电脑睡眠醒来时，迟了超过 15 分钟的预约不再显示。

### 窗口：`widget.window`

```js
const { width, height } = await widget.window.getSize();
await widget.window.setSize(320, 200);   // 会被限制在 size 的 min/max 之内
```

### 外观和事件

```js
// 目前的主题和外观值
widget.appearance.get();

// 换主题或改外观时（CSS 变数已经更新好了）
widget.appearance.onChange((a) => {});

// 锁定、层级、鼠标穿透改变时：{ locked, layer, clickThrough }
widget.on("state", (s) => {});

// 被快捷键叫出来时（目前是便签和待办列表的快捷键，叫出 winwidget.notes、winwidget.todo）：把游标放进主要的输入框
widget.on("summon", () => {});

// 写进 WinWidget 的日志
widget.log("讯息", { any: "data" });
```

## 生命周期：ready → show → hide → unload

一张卡片从被加载到被移除，外壳会按固定顺序发事件。全部用 `widget.on(名称, 回呼)` 订阅，回传值是退订函式。

| 事件 | 什么时候来 | 内容 |
|---|---|---|
| `ready` | 页面起来了（DOMContentLoaded 之后再过一个工作，所以你写在 DOMContentLoaded 里的订阅一定听得到） | `{ visible }` |
| `show` | 卡片出现在屏幕上。**开机那次也算一次**，带 `initial: true` | `{ from, visible: true, initial }` |
| `hide` | 卡片离开屏幕：隐藏全部、托盘单张隐藏、全屏幕让位、`window.hide()` | `{ from, visible: false, initial: false }` |
| `resize` | 卡片尺寸变了（拖边、拖角、控制中心改大小）。连续变化会**去抖 80ms**，只回报停下来的那一个 | `{ width, height }`，CSS 像素 |
| `unload` | 卡片要被移除、或整个程序要结束 | `{ kill: true }` |

`from` 说明这次显示/隐藏是谁造成的：

| `from` | 谁 |
|---|---|
| `startup` | 开机跟着外壳一起显示 |
| `tray` | 托盘菜单（显示/隐藏全部、单张显示/隐藏） |
| `control` | 控制中心（“定位”、显示全部开关） |
| `hotkey` | 全域快捷键叫出来 |
| `fullscreen` | 有别的全屏幕程序，这张卡片让开或回来 |
| `api` | 卡片自己呼叫 `widget.window.show()` / `hide()` |

### 顺序保证

1. `ready` 一定比第一个 `show` 早。所以“启动时要做一次”的初始化写在 `ready` 里，不会被 `show` 打乱。
2. 已经在屏幕上的卡片（开机默认）会在 `ready` 后立刻收到 `show{ initial: true }`；启动时被隐藏的（例如开了“隐藏全部”）不会收到，等真的显示才有。
3. `show` / `hide` 是成对的，而且同一个状态不会重复发：`hide` 之后再 `hide` 没有第二次；`show` 之后再 `show` 也没有。用 `widget.visible` 随时查目前状态。
4. `hide` 会在卡片仍活着的时候到，`unload` 是“这次真的要走了”。只做一次的事（保存、关定时器）放 `unload`，暂停动画放 `hide`。

```js
// 边跑边省电：看不见就停，回来再算一次
let timer = 0;
function start() {
  if (timer || !widget.visible) return;
  timer = setInterval(tick, 1000);
  tick();
}
function stop() {
  clearInterval(timer);
  timer = 0;
}

widget.on("ready", () => start());
widget.on("show", ({ from, initial }) => {
  widget.log("shown", from, initial);   // from 见上表
  start();
});
widget.on("hide", () => stop());
widget.on("unload", ({ kill }) => {
  stop();
  if (kill) widget.storage.set("lastSeen", Date.now());
});

// 尺寸变了再排版（不用听 window 的 resize，那是整窗，带 DPI 换算）
widget.on("resize", ({ width, height }) => {
  document.body.dataset.compact = width < 260 ? "1" : "";
});
```

`widget.visible` 是随时可读的目前状态，SDK 会跟着 `show` / `hide` 更新。卡片刻意不去抢键盘焦点，所以没有 focus / blur 事件；要用键盘输入的组件，自己在卡片里放输入框，用户点它才会拿到键盘。

### 和 uTools 那七个事件的对照

uTools 的事件是“外挂程序 vs 主窗口”的模型；WinWidget 的卡片本身就是一个独立窗口，所以只能对到形状相同的那几个：

| uTools | WinWidget | 差在哪 |
|---|---|---|
| `onPluginReady(cb)` | `widget.on("ready", cb)` | 一样只在加载后一次。uTools 会等 `cb` 的 Promise；这里不会等，要“等完再进”用 `utools.onPluginReady` |
| `onPluginEnter(cb)` | `widget.on("show", cb)` | 参数形状见下；每次显示都触发，不只是第一次 |
| `onPluginOut(cb)` | `widget.on("hide", cb)` + `widget.on("unload", cb)` | `hide` 对应 `isKill: false`，`unload` 对应 `isKill: true` |
| `onPluginDetach(cb)` | 无 | 卡片本来就是独立窗口，没有“分离”这一步；`utools.onPluginDetach` 会登记但不触发 |
| `onScheduleTrigger(cb)` | `utools.onScheduleTrigger(cb)` | 一样。自写的 cron 到点会真的调 `cb`，`{ code, label, at }` |
| `onMainPush(cb, onSelect?)` | `utools.onMainPush(cb)` | 有，语意是“带着 payload 被唤起”：`redirect(label, payload)` 命中本组件的动态功能后，向被唤起的那张卡片推 `mainPush`，`cb(action, payload)` 收 `{ code, type, payload, from }`。`onSelect` 不实作（没有结果列表可选） |
| `onDbPull(cb)` | `utools.onDbPull(cb)` | 有，但是**降级**：没有云端，只是同一个组件的其他卡片改了文档时，向本组件的每张卡片广播 `{ direction: "pull", docs: [...] }` |

`utools.onPluginEnter` 的参数按 uTools 的 `PluginEnterAction` 给：`{ code, type: "text", payload: "", from }`，`from` 是 uTools 的词（`main` / `panel` / `hotkey` / `redirect`），由上表的 `from` 映射过来：`startup`、`fullscreen` → `main`，`tray` → `panel`，`hotkey` → `hotkey`，`control`、`api` → `redirect`。`option` 只有在“从推送结果进来”时才有，这里不会有。

## 开自己的窗口：createBrowserWindow

卡片本身是 uTools 说的 **main window**（`utools.getWindowType()` → `"main"`）。要开设置面板、预览窗、全屏幕展示这种第二个窗口，用 `utools.createBrowserWindow(url, options, callback)`：定义照 uTools / Electron 的 `BrowserWindow`，同一份页面在这种窗口里 `getWindowType()` → `"custom"`。

```js
const win = utools.createBrowserWindow(
  "panel.html?mode=edit",              // 组件文件夹里的 HTML，可以带 query
  {
    width: 520, height: 380,           // 页面区域，不含标题列
    title: "设置",
    show: false,                       // 先别露面，等 callback 再显示，避免白屏
    resizable: true,
    alwaysOnTop: true,
    backgroundColor: "#0f1a24",
  },
  (w) => {
    w.show();                                    // 页面 ready 了才显示
    w.webContents.send("hello", "从卡片来");      // 卡片 → 窗口
  }
);
win.on("closed", () => widget.log("窗口被关掉"));
```

### 这个窗口是什么

- 它是同一个组件的页面：同一个 origin（`<组件 id>.widgets.localhost`）、同一份 `localStorage`、同一套主题和 SDK。所以 `widget.storage`、`widget.settings`、`utools.dbStorage` 两边看到的是同一份数据。
- 页面里 `widget.windowType === "custom"`、`widget.windowId` 是这个窗口的号码；`utools.getWindowType()` 回 `"custom"`。卡片那边是 `"main"`、`windowId` 是 `0`。
- 号码从 1 开始，一个组件同时最多 24 个窗口。
- 卡片被移除、或整个程序结束时，它开的窗口一起关掉（先关子窗口，再关父窗口）。

### options（BrowserWindowConstructorOptions）

| 字段 | 默认 | 说明 |
|---|---|---|
| `width` / `height` | 800 × 600 | 页面区域大小（DIP，会按屏幕缩放换算） |
| `minWidth` / `minHeight`、`maxWidth` / `maxHeight` | 无 | 拖边的上下限 |
| `x` / `y` | 置中 | 左上角位置 |
| `center` | — | `true` 开在目前屏幕中央 |
| `show` | `true` | 建议先 `false`，在 callback 里 `show()` |
| `title` | 空 | 标题列文字（`getTitle()` 回这个值） |
| `resizable` | `true` | 能不能拖边改大小 |
| `closable` | `true` | `false` 时关不掉，连 `window.close()` 也不行 |
| `frame` | `true` | `false` → 无边框；圆角跟 `roundedCorners` |
| `alwaysOnTop` | `false` | 置顶 |
| `skipTaskbar` | `false` | 不进工作列 |
| `opacity` | 1 | 0–1，整窗透明 |
| `backgroundColor` | 白 | `"#0f1a24"`、`"rgba(15,26,36,0.9)"` 都行 |
| `transparent` | `false` | 真要透明底才开，配 `frame:false` |
| `fullscreen` | `false` | 全屏幕 |
| `webPreferences.preload` | — | **不会执行**（没有 Node）；页面侧改用下面的 `ipcRenderer` |

`movable`、`maximizable`、`minimizable`、`focusable`、`hasShadow`、`titleBarStyle`、`acceptFirstMouse`、`enableLargerThanScreen`、`fullscreenable` 这些旗标：接受，但 Windows 上不一定有对应；写了不会报错。

### BrowserWindow

| 方法 | 说明 |
|---|---|
| `id` / `webContents` | 号码、页面物件 |
| `show()` / `showInactive()` / `hide()` | 显示、显示但不抢焦点、隐藏 |
| `close()` / `destroy()` | 关掉 |
| `isVisible()` / `isDestroyed()` / `isFocused()` | 状态 |
| `focus()` / `blur()` / `moveTop()` | 焦点、放到最上层 |
| `getSize()` / `setSize(w, h)` | 页面区域宽高（**不含标题列与边框**） |
| `getContentSize()` / `setContentSize(w, h)` | 同上（WebView2 没有内外之分） |
| `getPosition()` / `setPosition(x, y)` | 外框左上角位置 |
| `getBounds()` / `setBounds(b)` | 位置 + 页面区域大小 |
| `getNormalBounds()` / `getContentBounds()` / `setContentBounds(b)` | 和上面同值（没有最大化还原态） |
| `getMinimumSize()` / `setMinimumSize(w, h)`、`getMaximumSize()` / `setMaximumSize(w, h)` | 上下限 |
| `center()` | 移到屏幕中间 |
| `setResizable(b)` / `isResizable()`、`setClosable(b)` / `isClosable()` | 能不能拖边、能不能关 |
| `maximize()` / `unmaximize()` / `isMaximized()` | 最大化 |
| `minimize()` / `restore()` / `isMinimized()` / `isNormal()` | 最小化 |
| `setFullScreen(b)` / `isFullScreen()` | 全屏幕 |
| `setAlwaysOnTop(b)` / `isAlwaysOnTop()` | 置顶 |
| `setTitle(t)` / `getTitle()`、`setBackgroundColor(c)` / `getBackgroundColor()` | 标题、底色 |
| `setSkipTaskbar(b)` / `setIgnoreMouseEvents(b)` / `setOpacity(o)` | 工作列、鼠标穿透、透明度 |
| `webContents.send(channel, ...args)` | 送到这个窗口的页面 |
| `webContents.executeJavaScript(code)` / `reload()` | 执行、重新加载 |
| `webContents.openDevTools()` / `closeDevTools()` / `isDevToolsOpened()` | 开发者工具 |
| `on("loaded" \| "closed", fn)` | 页面 ready、窗口关掉（`createBrowserWindow` 的 callback 就是 `loaded`） |

尺寸语义：`getSize()` 回的是**页面区域**（你设置的 `width` / `height`），不是含标题列的外框；位置 `getPosition()` 是外框左上角。所以 `setSize(w, h)` 之后 `getSize()` 一定回同一组数字。

### 两边怎么讲话

| 方向 | 怎么做 | 另一边怎么收 |
|---|---|---|
| 卡片 → 窗口 | `win.webContents.send("channel", ...args)` | 窗口页面 `ipcRenderer.on("channel", (event, ...args) => …)` |
| 窗口 → 卡片 | `utools.sendToParent("channel", ...args)` | 卡片页面 `ipcRenderer.on("channel", …)`（或再开一个窗口时用 `win.webContents.send`） |
| 窗口被关 | 窗口页面 `window.close()` | 卡片 `win.on("closed", fn)` |

```js
// panel.js —— 窗口那一边
ipcRenderer.on("hello", (event, greeting) => {
  document.title = greeting;
});
document.getElementById("ok").onclick = () => {
  utools.sendToParent("save", { theme: "dark" });   // 卡片收得到
  window.close();                                   // 宿主会关掉这个窗口
};
```

`ipcRenderer.send(channel, ...args)` 在 uTools 里是发给 Electron 主行程；WinWidget 没有主行程，所以它等于 `utools.sendToParent`。`ipcRenderer.on` / `once` / `removeListener` / `removeAllListeners` 都有，收的是 `(event, ...args)`，`event` 只是个占位物件。

### 做不到的（会怎样）

下面这些方法照 uTools 的名字留着，呼叫时**不报错、也不静默**：宿主回 `{ unsupported: "＜原因＞" }`，相容层印一条 console 警告之后回 `undefined`。

| 方法 | 为什么 |
|---|---|
| `capturePage()` / `print()` / `printToPDF()` / `savePage()` / `takeHeapSnapshot()` | WebView2 没有对应的截图 / 打印 / 保存界面 |
| `loadURL()` / `loadFile()` | 窗口建好就绑定页面；要换页请新开一个窗口 |
| `setZoomFactor()` / `insertCSS()` / `removeInsertedCSS()` | 用页面自己的 CSS、`document.body.style.zoom` |
| `setAspectRatio()` / `setProgressBar()` / `setVisibleOnAllWorkspaces()` / `isVisibleOnAllWorkspaces()` | Windows 上没有对应 |
| `setContentProtection()` / `isContentProtected()` / `setKiosk()` / `isKiosk()` | 没有对应 |
| `flashFrame()` / `setEnabled()` / `isEnabled()` | 没有对应 |
| `setHasShadow()` / `hasShadow()` | 阴影跟系统设置走，不能单独控制 |
| `enableDeviceEmulation()` / `disableDeviceEmulation()` | WebView2 没有装置模拟 |
| `findInPage()` / `stopFindInPage()` | 卡片页用的是 `window.find()`，没有高亮计数 |

### 注意事项

- 开窗是**异步**的：`createBrowserWindow` 立刻回物件，但 `win.id` 要等窗口真的建好才有值（同步读是 `0`）；所有方法都会等建好才生效，照上面的写法直接用就行。
- 窗口和卡片共用 origin 与 CSP：不要把“只有卡片能看”当成安全边界。
- `show: false` + callback 里 `show()` 是 uTools 官方建议的写法；不这样做，页面还没画好就露面会闪白。
- 全屏幕透明置顶：`{ frame: false, transparent: true, skipTaskbar: true, alwaysOnTop: true }`，再用 `setBounds()` 盖住目标屏幕。

## 外观：跟着主题走

WinWidget 有几套主题，用户也能在控制中心调整背景、文字颜色、强调色、字体、字号、圆角、内边距和透明度。只要你的组件用下面这些变数和样式，这一切都会自动生效。

### 版面

- `<body>` 就是卡片：背景、圆角、边框、内边距都已经设好。内容直接放进 `<body>`。
- `<html>` 是透明的窗口，四周留了给阴影的空白，不要给它加背景。
- 字号用 `rem`：用户调“字号”时，`1rem` 会跟着变（默认 14px）。
- 卡片可能被缩放。用 flex/grid 排版；要按大小调整，可以在 `body` 上设 `container-type: size`，再用 `@container (max-height: 100px) { … }`。注意 `@container` 只能改 `body` 里面的元素，改不了 `body` 本身。

### 放大时内容跟着变大

在 `widget.json` 的 `size` 加上 `"grow": 1`，用户把卡片拉得比默认大时，整张卡片的内容会一起放大，字、图标、间距都按比例变大，不会只是多出空白：

```json
"size": { "width": 260, "height": 150, "minWidth": 180, "minHeight": 110, "grow": 1 }
```

- 放大的倍数是“宽放大几倍”和“高放大几倍”中较小的那个，最多 3 倍。例如拉到两倍宽、1.3 倍高，内容放大 1.3 倍，多出来的宽度交给你的排版。
- 比默认小时不会缩小，小尺寸要靠你自己的排版（上面的 `@container`）。
- `grow` 可以是 0 到 1 之间：列表类的组件写 `0.5`，拉大时字变大一点，同时多显示几项。
- 不写或写 `0`：和以前一样，只是多出空间。
- 卡片的圆角、边框和阴影不会跟着放大。目前的倍数在 CSS 变数 `--w-size-scale`。

### CSS 变数

| 变数 | 用途 |
|---|---|
| `--w-fg` | 主要文字颜色 |
| `--w-fg-muted` | 次要文字（标签、说明） |
| `--w-fg-faint` | 很淡的文字、分隔 |
| `--w-accent` | 强调色：进度、选中、重点数字 |
| `--w-on-accent` | 放在强调色上面的文字 |
| `--w-warn` `--w-danger` | 警告、危险 |
| `--w-bg` | 卡片背景（已用在 body 上） |
| `--w-bg-solid` | 卡片的颜色，但不透明：用在要挡住后面内容的地方，例如弹出的列表 |
| `--w-border` `--w-rule` | 边框、分隔线 |
| `--w-track` | 进度条的底 |
| `--w-control-bg` `--w-hover` | 输入框底色、滑过时的底色 |
| `--w-font` | 内文字体 |
| `--w-font-num` | 数字的字体 |
| `--w-font-display` | 组件里那个最大的数字（时间、温度）的字体 |
| `--w-font-title` | 标题字体 |
| `--w-radius` `--w-padding` | 卡片圆角、内边距 |

### 现成的样式

| class | 用途 |
|---|---|
| `w-label` | 小号、次要颜色的标签文字 |
| `w-title` | 标题 |
| `w-num` | 数字（等宽、主题的数字字体） |
| `w-display` | 最大的那个数字 |
| `w-rule` | 分隔线（用在 `<hr>` 或 `<div>`） |
| `w-bar` | 进度条：`<div class="w-bar"><i style="width:40%"></i></div>`；加 `is-warn` 变成警告色 |
| `w-input` | 输入框 |
| `w-btn` | 按钮；加 `is-primary` 变成强调色按钮 |
| `w-check` | 圆形勾选框：`<button class="w-check" aria-pressed="true">` |

### 按主题微调

`<html>` 上有这些属性，可以写专门的样式：

```css
/* 某一套主题 */
html[data-theme="paper"] .quote { font-style: italic; }

/* 用户选了毛玻璃卡片 */
html[data-style="frosted"] .quote { letter-spacing: 0.02em; }

/* 组件被锁定时 */
html[data-locked="true"] #next { display: none; }
```

用户也可以在控制中心“外观 → 自订 CSS”给单一组件加样式，它会排在你的 CSS 之后。

### 省电：每秒更新的东西不要加动画

组件整天开着，每一帧画面都要算。每秒更新一次的数字或进度条，如果加了 0.5 秒的 `transition`，画面就几乎一直在动，一个组件可以吃掉 20% 的处理器核心；不加的话只要 1%。

- 每秒或更频繁更新的元素，不要 `transition` 和 `animation`。`w-bar` 默认有 0.5 秒的宽度动画，每秒更新时写 `.w-bar > i { transition: none; }`。
- 不要 `animation: … infinite`；要闪烁提示，给一个次数（例如 `8`）。
- 指针、转盘这类要转的东西，放在独立的元素上用 CSS `transform` 转，不要每秒重画整个 SVG。
- 每分钟才变的东西，就每分钟才更新（`setTimeout` 对准下一分钟）。

## 拖动、菜单和点击

WinWidget 已经帮你处理好：

- **拖动**：在卡片任何地方按住拖动，就能移动组件。按钮、链接、输入框不会触发拖动；其他元素不想被拖动时，加上 `data-no-drag`。
- **右键**：显示 WinWidget 的组件菜单。某个区域要自己处理右键时，加上 `data-no-menu`。
- **缩放**：`size.resizable` 不是 `false` 时，右下角会有缩放手把。
- **锁定**：用户锁定组件后不能拖动和缩放；你可以用 `widget.locked` 和 `html[data-locked]` 知道。

## 权限

组件默认只能显示自己的内容：不能连网、读不到系统信息、也碰不到你电脑上的文件。要用到这些，在 `widget.json` 的 `permissions` 里声明：

| 权限 | 允许 |
|---|---|
| `system` | `widget.system`：处理器、内存、网速、磁盘、电池 |
| `network:api.example.com` | 连到这个网站 |
| `network:*.example.com` | 连到 example.com 和它所有的子网域 |
| `network:*` | 连到任何网站（用户安装时会看到明显的提示，能不用就不用） |
| `shell.open` | `widget.shell.open`：用浏览器打开网址 |
| `notify` | `widget.notify`：显示 Windows 通知 |
| `audio` | `widget.audio`：读取和调整系统音量、静音 |
| `media` | `widget.media`：读取正在播放的歌名、封面，播放、暂停、切换曲目 |
| `clipboard` | `widget.clipboard`、`utools.copyText` / `copyImage` / `copyFile` / `getCopyedFiles`：读取和写入剪贴簿里的文字、文件和图片（用户允许时会看到明显的提示） |
| `screen` | `widget.screen.capture`、`utools.screen.*` / `utools.captureScreen` / `utools.screenColorPick`：屏幕列表、坐标换算、截图、取色（用户允许时会看到明显的提示） |
| `input` | `utools.hideMainWindowTypeString`：把文字直接打到前一个窗口（用户允许时会看到明显的提示） |
| `schedule` | `utools.requestSchedule` / `getSchedules` / `removeSchedule`：登记定时任务（用户允许时会看到明显的提示） |
| `sharp` | `utools.sharp`：在宿主里处理图片（用户允许时会看到明显的提示） |
| `ubrowser` | `utools.ubrowser`：抓取网页内容（用户允许时会看到明显的提示） |
| `shell.launch` | `widget.shell.launch`、`pick`、`save`、`reveal`、`trash`、`info`、`paths`、`fileIcon`：打开程序和文件、选文件、选保存位置、在资源管理器里显示、丢进资源回收筒、读取名称和图标（用户允许时会看到明显的提示） |

读取文件夹不用声明权限：用户在设置里选了哪个文件夹，组件就只能读那个文件夹里的图片，见 [`widget.files`](#读取用户选的文件夹widgetfiles)。

**谁来允许：**

- 用“新建组件”建立的组件是你自己写的，声明的权限直接生效。
- 别人的组件，安装时会列出它要的权限，用户按“安装”才算允许。更新后多要了权限，用户要再允许一次，在那之前新权限用不了。
- 把别人的组件文件夹直接放进组件目录的话，第一次放上桌面时会先请用户允许。

**连网的规则：** 不只 `widget.fetch`，页面里直接加载的图片、字体、脚本、`fetch()` 和 WebSocket 也只能连到允许的网站。差别是：直接 `fetch()` 要对方网站支持 CORS，`widget.fetch` 不用。

## 打包和分享

`.fwz` 就是把组件文件夹压成 zip、改了副档名。

- **导出**：控制中心“添加组件”→ 你的组件卡片 →“导出 .fwz”。隐藏的文件和文件夹（例如 `.git`）以及 `node_modules` 不会被打包。
- **安装**：双击 `.fwz` 文件、把它拖到控制中心窗口上，或在“添加组件”按“安装 .fwz 文件…”。安装前会显示名称、作者、版本和需要的权限。
- **更新**：改大 `version` 再导出。`id` 相同的组件会被替换，桌面上的组件、设置和保存的数据都会保留；旧版本移到资源回收筒。
- **用框架写**：React、Vue、Svelte 都可以，只要输出静态文件。把建置结果（例如 `dist/`）和 `widget.json` 放在一起，`entry` 指向它的 `index.html`；资源路径要用相对路径（例如 Vite 设 `base: "./"`）。
- **大小限制**：`.fwz` 最大 64 MB，解压后最多 256 MB、5000 个文件。

### 装 uTools 外挂（`.upx`）

同一个“安装 .fwz / .upx…”按钮（以及拖放到控制中心）也认 uTools 的 `.upx`。它其实是 gzip 包着“16 字节头 + JSON 目录 + 4 字节对齐 + 文件数据”，WinWidget 会就地拆开，用 `plugin.json` 生成一份 `widget.json`：

| `plugin.json` | 变成 |
| --- | --- |
| `name`（一串小写字母数字） | `id`；缺失或不合规时按 `pluginName` 散列成 `uplugin-xxxxxxx` |
| `pluginName` | `name`（中文名照原样显示） |
| `main` / `logo` | `entry` / `icon` |
| `version` / `author` / `description` | 同名字段 |
| `features` / `preload` | 记在 `widget.json` 的 `utools` 区块里，仅作留痕 |

权限是从页面程序码里扫出来的（看到 `utools.copyText` 就给 `clipboard`，看到 `utools.screen.*` 就给 `screen`，依此类推），安装前的确认框会照常列出来让你决定。

一个已知的天花板：uTools 的 `preload.js` 跑在 Node.js 里，而 WinWidget 的页面跑在 WebView2 里，没有 Node。所以**纯网页外挂**（HTML + JS + jQuery 之类）能直接跑；**依赖 preload 的外挂**装得进来、页面也能开，但 `preload` 提供的能力不可用。日志里会写一条 `upx: "…" declares preload.js — Node.js is not available in this host`。

### `.upxs`：新版市场安装包读不了，从已安装的外挂转过来

uTools 自 5.0.0 起把市场安装包换成了 `.upxs`：整包加密、附开发者签名，用来保证“来自可信任开发者、没被改过”。WinWidget 没有这把钥匙，所以拖 `.upxs` 进来只会得到一句明确的提示，而不是假装解包成功：

```
没办法安装这个文件
this is a uTools UPXS package (encrypted and signed since uTools 5.0).
WinWidget has no key for it, so the files cannot be read here.
```

官方 changelog 的原话是“安装包格式升级为 UPXS 格式。这一格式不仅具有加密功能，还包含开发者信息签名”。实测那个 1.6 MB 的文件，除了头 4 个字节（`c8 01 00 00`）之外整块熵值都是 8.0，找不到 zip／gzip／JSON 的任何痕迹，也不是异或那种能靠频率分析还原的东西。

可行的路子是**先在 uTools 里装好，再把装好的外挂搬过来**：uTools 解出来的外挂放在 `%APPDATA%\uTools\plugins\`，是一个个 `.asar`（Electron 的封存，**没有加密**）。WinWidget 直接认这种文件：

1. 在 uTools 里正常安装那个外挂；
2. 到 `%APPDATA%\uTools\plugins\` 找到对应的 `<一串 hash>.asar`（不确定是哪个就用“添加组件”页的导入按钮逐个试，安装确认框会显示外挂名）；
3. 在控制中心“添加组件”→“安装 .fwz / .upx…”选中它，或者直接把 `.asar` 拖到控制中心。

`.asar` 的头是 `[u32 4][u32 pickle][…][u32 jsonLen]`，数据区从 `8 + pickle` 开始，目录项是 `{size, offset:"…", unpacked?, link?}`——和 `.upx` 只差一个头，所以两者共用同一套“拆包 → 用 `plugin.json` 合成 `widget.json`”的流程。带 `unpacked` 标记的文件（原生模组之类）从旁边的 `<名字>.asar.unpacked\` 目录读。

顺带说明：`utools.getAppVersion()` 报的是**相容级别**（目前 `7.6.0`），不是 WinWidget 自己的版本号。外挂普遍写 `parseFloat(utools.getAppVersion()) < 7` 判断底座够不够新，报 1.0.0 会让它们直接画一张“uTools 版本太低”的页面挡住一切。

### 带 `preload.js` 的外挂：`window.services` 接桥

uTools 的 `preload.js` 跑在 Electron 的 preload 里，`require("fs")`、`require("electron")` 都有；WinWidget 的页面在 WebView2 里，没有 Node。所以带 preload 的外挂以前会白屏——页面第一次碰 `window.services.xxx()` 就抛 `Cannot read properties of undefined`，整页 React 挂不上去。

现在宿主会往每个组件页注入 `services.js`（在 `utools.js` 之后），用**同名的方法**把 `window.services` 接成宿主桥：

| preload 里的方法 | 现在由谁答 |
| --- | --- |
| `readAllRecords` / `removeRecords` / `clearAllRecords` | 宿主的剪贴板历史：`clipboard.history`，存在 `data\clipboard-history.json`（最近 300 条，文字和文件） |
| `listenAppendRecord(cb)` | 宿主每 700ms 扫一次剪贴板，有新内容就推给页面 |
| `filesExists(paths)` | `clipboard.filesExist` |
| `executeCopy` / `executePaste` | 转给 `utools.copyText` / `copyFile` / `hideMainWindowPasteText` / `hideMainWindowPasteFile` |
| `dragToFiles`、`pinScreen`、`mcpPinData` 等 | 目前只是 no-op，会在控制台留一行“not bridged” |

`window.services` 只有在页面自己没有时才会被装上；页面里已经有自己的桥就不动它。

实测（uTools 的“剪贴板”外挂，`69699f4f…asar`）：卡片开出来是正常的列表，复制任何东西都会立刻出现在最上面，文件记录显示“1 个文件”，点条目复制／贴上都可用。还差的部分写在下面。

两点值得记住：

- **历史只在宿主执行期间记录**。想抓更早的内容，得先有页面在跑（第一次 `clipboard.history` 会启动监听）。图片暂时不收，所以“图像”那一栏是空的。
- **装包时的确认框就是授权**。以前导入完成只写 `permissions`，用户还得自己到控制中心点“允许”；现在安装会把确认框里列出的权限写进 `grants`，并把已经开着的旧页面重载一遍，不会再出现“装好了但每个呼叫都 permission denied”。

还没接的：`setSubInput`（外挂顶部的搜寻框，uTools 宿主自己画的）、钉图／贴边窗口、把记录拖成文件。

### 剪贴板历史：一套给 JS 用的完整界面

宿主自己维护一份历史（`data\clipboard-history.json`，最近 300 条，`type` 为 `text` / `image` / `files`，最新在前），并把读写都摊成方法。组件里用 `widget.clipboard.*`，uTools 外挂里用 `window.services.*`：

| 方法（`widget.clipboard.*`） | 参数 | 作用 |
| --- | --- | --- |
| `history(opts)` | `{type, pinned, limit}` | 取记录；`type` 是 `text`/`image`/`files`/`all`，`pinned` 只看收藏 |
| `stats()` | — | `{all, text, image, files, pinned}`，就是四个分类标签上的数字 |
| `pin(ids, pinned)` | 记录 id 或 hash 的阵列 | 收藏／取消收藏（`pinned` 默认 `true`） |
| `remove(ids)` | 同上 | 删除若干条 |
| `clear(opts)` | `{keepPinned}` | 清空；`keepPinned: true` 只留收藏 |
| `copy(id)` | 记录 id | 把这条塞回系统剪贴板 |
| `image(id)` | 记录 id | 图片记录的 PNG data URL |
| `filesExist(paths)` | 路径阵列 | 文件是否还在，回传布林阵列 |

对应的宿主方法名是 `clipboard.history` / `.stats` / `.pin` / `.remove` / `.clear` / `clipboard.recopy` / `clipboard.image` / `clipboard.filesExist`，都要求 `clipboard` 权限。

“执行贴上”不需要新界面：`utools.hideMainWindowPasteText/File/Image` 已经是“收起卡片 → 还原前景窗口 → Ctrl+V”，剪贴板里放了什么就贴什么，所以 `copy` 之后呼叫它就行。

图片记录怎么落地：截图进剪贴板时，宿主把 PNG 存到 `data\clipboard\images\<hash>.png`，记录里 `value` 记路径、`size` 记字节数。uTools 的外挂是按 `utools.db.getAttachment("attachment/" + hash)` 取图的，所以页面第一次读到这条记录时，`services.js` 会把字节**补传成该组件自己的附件**（`attachment/<hash>`），再把 `value` 改写成附件 id——列表缩图和收藏流程就都走同一条路。

收藏是两条腿：外挂自己用 `collect/<hash>` 文件 + `utools.db.promises.allDocs("collect/")` 记一份，宿主记录上另有 `pinned` 字段（`clipboard.history.pin`）。为了让前者能用，`utools.js` 的 `db.allDocs` 现在接受前缀字串（以前只认 `{idStartsWith}`），`db.getAttachment` 回传的物件也带上了 `buffer` / `byteLength` / `length`（uTools 给的是 Node `Buffer`，外挂普遍写 `new Blob([n.buffer])`），`db.postAttachment` 收 `ArrayBuffer` / `TypedArray`。

监聴是**变动骓动**的：宿主每 700ms 只看一次 `GetClipboardSequenceNumber()`，誈数器没动就什鮨都不读。

## 十六个分类：每一类怎么用

WinWidget 的能力划分跟 uTools 官方文件一致，页面上用 `utools.*` 的名字。这一节按分类给最小例子；型别都在 `widget.d.ts` 的 `WinWidget.Utools` 里。

### 屏幕

```js
const displays = await utools.screen.getAllDisplays();   // Display[]，坐标是 DIP
const primary = await utools.screen.getPrimaryDisplay();  // { scaleFactor: 1.5, bounds, workArea, … }
const win = await utools.screen.captureDisplay(0);        // NativeImage
const size = await win.getSize();                         // { width, height }（像素）
const png = await win.toPNG();                            // Uint8Array
const dip = await utools.screen.screenToDipPoint({ x: 400, y: 300 });
```

`NativeImage` 的 `getSize` / `toPNG` / `toJPEG` / `crop` / `resize` / `toDataURL` 都是 Promise：宿主先把 PNG 抓回来，页面才能解码。`utools.screenColorPick()` 直接回光标下的 `{ hex, rgb }`，不会像 uTools 那样弹放大镜等你点。

`utools.screen.captureInteractive(timeout?)` 走的是 **Windows 自带的截图浮层**（`ms-screenclip:`，也就是截图工具 / Snipping Tool 的框选界面）：宿主把它拉起来，轮询剪贴簿序号，用户在浮层里框完，宿主把剪贴簿里的图取回来。回 `NativeImage`；用户按 Esc 取消或超时（默认 45 秒）回 `null`。注意看到的是系统界面，不是 WinWidget 自绘的选区，而且那一刻鼠标属于截图浮层。

### 输入

```js
// 卡片会先藏起来，接着在前一个窗口里粘贴
await utools.hideMainWindowPasteText("Hello");
await utools.hideMainWindowPasteFile(["D:\\a.pdf"]);
await utools.hideMainWindowPasteImage("data:image/png;base64,…");
await utools.hideMainWindowTypeString("逐字打到光标处");
```

粘贴走剪贴簿 + `Ctrl+V`，所以需要 `clipboard` 权限；打字注入要 `input` 权限。

### 复制

```js
await utools.copyText("一段文字");
await utools.copyFile(["D:\\a.pdf", "D:\\b.zip"]);     // CF_HDROP
await utools.copyImage("data:image/png;base64,…");
const files = await utools.getCopyedFiles();            // [{ path, isDirectory, isFile, name }]
```

### 数据库

```js
const res = await utools.db.put({ _id: "note-1", text: "hi" });
const doc = await utools.db.get("note-1");               // 带 _rev 的文档
await utools.db.remove(doc);
await utools.db.postAttachment("note-1", base64, "image/png");
const image = await utools.db.getAttachment("note-1");   // NativeImage
```

文档存在 `data/db/<组件 id>.json`，附件存在同名的 `<组件 id>.attachments/` 目录；单文档上限 1 MB、单附件 10 MB。`dbStorage` 还是本组件的 local storage（同步、适合小设置）。

### 定时任务

```js
await utools.requestSchedule({
  code: "morning",
  label: "每天九点的提醒",
  trigger: { cron: "0 9 * * *" },       // 分 时 日 月 周，标准 5 位
});

utools.onScheduleTrigger(async (action) => {
  // action = { code, label, at }
  await utools.showNotification("该起床了");
});

const list = await utools.getSchedules();  // 带 successCount / failureCount / lastStatus
await utools.removeSchedule("morning");
```

`trigger` 也可以直接给一个时间戳（一次性任务，错过一分钟会补触发一次）。`trigger.startTime` / `endTime` 限定生效区间，过了 `endTime` 任务自动消失。回调抛错或 reject 会被记成失败。

### 模拟操作

```js
await utools.simulateKeyboardTap("v", "ctrl");
await utools.simulateMouseMove(300, 200);
await utools.simulateMouseClick(300, 200);
await utools.simulateMouseDoubleClick(300, 200);
await utools.simulateMouseRightClick(300, 200);
```

坐标是**物理像素**，不按 DPI 缩放——与 uTools 的定义一致；要跟 `screen` 的 DIP 坐标互换，用 `dipToScreenPoint`。需要 `input` 权限。

### 动态功能

```js
await utools.setFeature({
  code: "site",
  cmds: ["打开站点", { type: "regex", label: "搜索", match: "^搜 (.+)$" }],
});
const features = await utools.getFeatures(["site"]);
await utools.removeFeature("site");   // 回 boolean
```

存在 `data/features.json`，控制中心读同一份。

`Cmd` 的五种 `type` 都会真的参与匹配，不再只是存着：

| `type` | 匹配什么 |
|---|---|
| 裸字串 | 当作精确的命令标签 |
| `over`（缺省） | `match` 作为子字串出现在输入文本里 |
| `regex` | `match` 当正则（`regex-lite`），可用 `exclude` 反向排除；坏正则永远不匹配 |
| `files` | 拖进来的文件，按 `extensions` 后缀匹配（大小写不敏感） |
| `img` / `window` | 永不匹配文本 |

选中框里输入的那段文字（例如 `https://example.com/x`）会用 `regex` / `over` / `files` 里的 `minLength` / `maxLength`（按字元数）先筛一遍，再逐条匹配。`utools.redirect("https://example.com/x", payload)` 能靠这条匹配唤起组件，同时把 `payload` 推给它——见下面的 `onMainPush`。

### 快捷入口

```js
await utools.redirect("打开站点");                 // 单独一个命令名
await utools.redirect(["另一个组件", "打开站点"]);  // [插件名, 命令]
await utools.redirectHotKeySetting("打开站点");     // 打开控制中心的快捷键页
const keys = await utools.getCmdHotKey("打开站点"); // "Ctrl+Shift+A" 或 null
```

找到的组件已经在桌面上就直接显示，没显示就加一张卡；找不到回 `false`。

### uBrowser

```js
const page = await utools.ubrowser.goto("https://example.com").run();
// { url, title, text, html, skipped }
```

只有抓取，没有内嵌浏览器：`click` / `input` / `wait` 之类会抛 `utools.unsupported`，`skipped` 会列出被跳过的步骤。需要 `ubrowser` 权限。

### Sharp

```js
const out = await utools
  .sharp("D:\\photo.jpg")
  .resize(800)
  .rotate(90)
  .grayscale()
  .jpeg({ quality: 85 })
  .toBuffer();       // Uint8Array

await utools.sharp("D:\\photo.png").resize(240, 240).toFile("D:\\thumb.png");
const meta = await utools.sharp("D:\\photo.png").metadata();
```

实作的是 `image` crate 能覆盖的算子；`tint` / `median` / `composite` / `trim` / `normalize` 会抛名说明原因。需要 `sharp` 权限。

### AI、FFmpeg、支付

这三类预留了分类文件、**没有实作**。调用会拿到 `reserved in the ai category — …` 这样的错误，不会假装成功。

## 和 uTools 插件的关系（相容到哪一步）

uTools 的插件是 Electron 应用：`plugin.json` + `preload.js`（在 Node 环境里 `require("fs")`、装 Sharp / FFmpeg）+ 页面。WinWidget 是 Rust + WebView2，**没有 Electron，也没有 Node**，所以 uTools 插件不可能原样搬进来。能搬的是“页面 + 页面上呼叫 `utools.*` 的那部分能力”：每个组件页都会被注入一份 `utools` 相容层（`/__fw/utools.js`），把它接到 WinWidget 自己的宿主能力上。

### 想把一个现成 uTools 插件的画面搬进来

1. 把插件的 `index.html`、CSS、JS 放进一个组件文件夹；
2. 在 `widget.json` 里按它用到的能力声明 `permissions`（`showNotification` → `notify`、`copyText` → `clipboard`、`captureScreen` → `screen`、`shellOpenPath` → `shell.launch`、`shellOpenExternal` → `shell.open`）；
3. 页面上呼叫的 `utools.*` 由相容层处理，不必改程序码。

**不要指望**：`preload.js`、`require(...)`、`process`、`fs`、`child_process`。这些在 WinWidget 里不存在，把 preload 原封不动搬进来只会得到一片空白。页面上用到的 `ipcRenderer` 有相容层（见“开自己的窗口”那一章），它背后是本组件的窗口讯息，不是 Electron 的行程间通讯。

### 先问一句：这个 API 有没有

```js
if (utools.__compat.supports("captureScreen")) {
  const png = await utools.captureScreen();        // PNG data URL
} else {
  document.body.textContent = "这个宿主没有屏幕截图";
}
console.log(utools.__compat.degraded);    // 有，但语意变了
console.log(utools.__compat.unsupported); // 完全没有
```

### 依 uTools 文件的分类逐项对照

WinWidget 现在按 uTools 官方文件的 16 个分类划分能力，每一类在 `src/core/` 下有同名文件（`window.rs`、`screen.rs`、`input.rs`…），页面上用到的名字与 uTools 一致。

| uTools 的分类 | WinWidget 里的情况 |
|---|---|
| 事件 | `onPluginReady`、`onPluginEnter`、`onPluginOut(isKill)` 都有，顺序和 uTools 一致（ready 跑完才 enter，隐藏是 `false`、移除/结束是 `true`）；`onPluginDetach` 会登记但不触发（每张卡片本来就是一个窗口）；`onScheduleTrigger` 现在**真的会触发**，见“定时任务”；`onMainPush` 也真的会触发（`redirect(label, payload)` 带 payload 唤起本组件时），`onDbPull` 降级为“同组件其他卡片改了文档”的本地广播 |
| 窗口 | `createBrowserWindow`（自订窗口，见“开自己的窗口”那一章）、`hideMainWindow`、`showMainWindow`、`outPlugin`、`getWindowType`（`"main"` / `"custom"`）、`sendToParent`、`setExpendHeight`（只改高度，而且是异步）、`findInPage` / `stopFindInPage`（走 `window.find`） |
| 系统 | `showNotification`、`shellOpenPath`、`shellOpenExternal`、`shellShowItemInFolder`、`shellTrashItem`、`shellBeep`、`getPath`、`getFileIconAsync`、`showOpenDialog`、`showSaveDialog`、`isDev`、`isWindows`…；`getPluginLocalDataPath` 回空字串（没有文件系统） |
| 屏幕 | `utools.screen` 一族：`getAllDisplays` / `getPrimaryDisplay` / `getDisplayNearestPoint` / `getDisplayMatching`（回 uTools 的 `Display`，坐标是 DIP）、`screenToDipPoint` / `dipToScreenPoint` / `screenToDipRect` / `dipToScreenRect`、`capture()` / `captureDisplay(n)`（回 `NativeImage`）、`captureInteractive(timeout?)`（拉起 Windows 自带截图浮层，框选完回 `NativeImage`，取消回 `null`）、`utools.screenColorPick()`（光标下的像素） |
| 输入 | `hideMainWindowPasteText` / `…PasteFile` / `…PasteImage` / `…TypeString` 都有：先把卡片藏起来，再把键盘交还前一个窗口，然后粘贴或打字。坐标类注入不在这里，见“模拟操作”；`input.startDrag` 仍未实作 |
| 复制 | `copyText`、`copyImage`（data URL / 路径 / `NativeImage`）、`copyFile`（一个或多个路径，写 `CF_HDROP`）、`getCopyedFiles()`（回 `{ path, isDirectory, isFile, name }`，这里是 Promise） |
| 数据库 | `utools.db` 全套：`put` / `get` / `remove` / `bulkDocs` / `allDocs` / `postAttachment` / `getAttachment` / `getAttachmentType` / `replicateStateFromCloud`，存在 `data/db/<组件>.json` 加附件目录里；`dbStorage` 仍是本组件的 local storage。**没有云端同步**，`replicateStateFromCloud()` 只回 `null`；`put` / `remove` / `bulkDocs` 之后会向同组件的其他卡片广播 `dbPull`（就是 `onDbPull`） |
| AI 能力 | 预留了分类文件，**没有实作**：调用会得到 `reserved in the ai category` 的说明 |
| 定时任务 | `requestSchedule(schedule)` / `getSchedules()` / `removeSchedule(code)` / `onScheduleTrigger(fn)`：标准 5 位 cron（`分 时 日 月 周`），也接受一次性时间戳；`startTime` / `endTime` 限定生效区间，过 `endTime` 自动删除。回调抛错或 reject 记成失败，`getSchedules()` 里能看到 `successCount` / `failureCount` / `lastStatus` |
| 模拟操作 | `simulateKeyboardTap(key, ...modifiers)`、`simulateMouseMove` / `Click` / `DoubleClick` / `RightClick(x, y)`。坐标单位是**物理像素**（与 uTools 一致，不按缩放换算） |
| 动态功能 | `getFeatures(codes?)` / `setFeature(feature)` / `removeFeature(code)`，存在 `data/features.json`，控制中心读同一份。`Cmd` 的 `type` 真的参与匹配（`over` / `regex` / `files` / `img` / `window`），见“动态功能”那一节 |
| 快捷入口 | `utools.redirect(label, payload)`（`label` 可以是 `[插件名, 命令]`，或单独一个命令名；找不到标签时再用动态功能的 `Cmd` 匹配这条输入，含 `type: "regex"`；带 `payload` 唤起时向目标卡片推 `mainPush`）、`redirectHotKeySetting(cmdLabel, autocopy)`（打开控制中心“设置”里的快捷键页）、`getCmdHotKey(cmdLabel)`（读设置里绑的键） |
| uBrowser 浏览器 | 只有页面抓取 `utools.ubrowser.goto(url).run()`，回 `{ url, title, text, html, skipped }`；没有内嵌浏览器，`click` / `input` 之类会抛 `utools.unsupported` |
| Sharp 图片处理 | `utools.sharp(input)` 链式：`resize` / `rotate` / `flip` / `flop` / `extract` / `extend` / `grayscale` / `negate` / `blur` / `sharpen` / `threshold` / `gamma` / `flatten`，输出 `png` / `jpeg` / `webp` / `tiff`，`toBuffer` / `toUint8Array` / `toFile` / `metadata`。`tint` / `median` / `composite` / `trim` / `normalize` 按名抛错 |
| FFmpeg 音视频处理 | 预留了分类文件，**没有实作** |
| 支付 | 预留了分类文件，**没有实作** |

新增的四个权限见上一节：`input`（打字注入）、`schedule`（定时任务）、`sharp`（图片处理）、`ubrowser`（页面抓取）。

没有实作或做不全的 API 不会安安静静回 `undefined`：呼叫时抛一个 `code: "utools.unsupported"` 的错误，讯息写明是哪一项、为什么。这样比 `TypeError: utools.xxx is not a function` 好查。语意变了的（同步变异步等）列在 `utools.__compat.degraded` 里。

### 新写组件不必绕 uTools

相容层是给“已经存在的网页”用的。新组件直接用 `widget.*`：型别完整（`widget.d.ts`）、有权限模型、跟主题走、错误讯息清楚。同一件事两边都有时，`widget.*` 是主路径，`utools.*` 是相容路径。

## 和外壳怎么对接（进阶）

前面几章的写法已经能做出完整的组件。这一章写给想知道“它到底怎么跑起来”的人：页面从哪来、外壳塞了什么进来、有哪些讯息、数据放在哪。看清楚这些，调试和做进阶功能都会快很多。

### 页面是怎么被加载的

WinWidget 不是用 `file://` 打开你的 `index.html`，而是启动一个只绑定 `127.0.0.1` 的小型 HTTP 服务，页面由它提供：

```
http://127.0.0.1:<端口>/__fw/<组件 id>/index.html
```

- **端口每次启动都可能不同**，所以永远写相对路径（`style.css`、`main.js`、`img/a.png`），不要写死 `127.0.0.1:8800`。
- 每一种组件有自己的 origin：`<组件id>.widgets.localhost`。`localStorage`、`IndexedDB`、`Cache` 都按 origin 隔离，同一种组件的多个实例共用这一份。
- 页面不能自行跳转到别的网址，也不能开新窗口；要开网页请用 `widget.shell.open`。
- 页面里加载的图片、字体、脚本，同样受 `permissions` 的 `network:` 限制。

### 启动时外壳塞进来的东西

在你的任何脚本执行之前，外壳会把这些放在 `window.__FW_BOOT__`：

| 字段 | 内容 |
|---|---|
| `settings` | 这个实例的全部设置值（已按语言折叠，见下） |
| `appearance` | 目前外观：`theme`、`style`、`shadow`、`themeCss`、`themeHref`、`userCss` 等 |
| `locked` | 是否被用户锁定 |
| `layer` | 目前的层级：`desktop` / `normal` / `top` |
| `clickThrough` | 是否开着鼠标穿透 |
| `state` | `{ edit, label }`：排列模式、卡片上那个名称标签 |
| `developer` | 是否在开发者模式 |
| `locale` | 用户语言，例如 `zh-TW` |
| `permissions` | 现在真的能用的权限（已声明且用户已允许的） |
| `hostVersion` | WinWidget 版本，例如 `1.0.0` |
| `widgetId` / `instanceId` | 组件 id、桌面上这一个的标识 |
| `size` | `{ width, height, grow }`，`width`/`height` 是默认尺寸 |
| `resizable` | 是否允许缩放 |

`widget-sdk.js` 读完这一份才建立 `window.widget`，所以你在 `main.js` 第一行就能用 `widget`。

### 讯息协议

`widget.*` 的每一个方法，最后都是一则讯息。想不通某个行为时，直接在开发者工具里看讯息最有效：

```js
// 呼叫：{ id, m, p }；外壳回：{ id, r } 或 { id, e: "错误讯息" }
chrome.webview.postMessage(JSON.stringify({ id: 7, m: "storage.get", p: { key: "todo" } }));

// 不需要回应的（拖动、开菜单）：{ m, p }
chrome.webview.postMessage(JSON.stringify({ m: "window.menu" }));

// 外壳主动推：{ ev: "settings" | "appearance" | "state" | "system" | "audio" | "media" | "identify", d: … }
chrome.webview.addEventListener("message", (e) => console.log(e.data));
```

日常用 SDK 就好，这一层是给你排查问题的：SDK 的错误讯息会前后带上目标，例如 `HTTP 404 (https://api.example.com/x)`。

### 外壳提供的方法一览

SDK 已经包好，下表是底层名称，方便你在开发者工具里对照：

| `ai.*` / `ffmpeg.*` / `payment.*` | 预留，一律回 reserved 错误 |

`log` 和 `ready` 没有回应，其余都会回。

|---|---|
| `/__fw/widget-sdk.js` | SDK（每个页面自动注入） |

### 数据放在哪

| 内容 | 位置 |
|---|---|
| 保存的数据（`widget.storage`） | `%AppData%\WinWidget\data\<实例标识>.json`，每个实例 2 MB |
| 你的组件文件夹 | `%AppData%\WinWidget\widgets\`（控制中心“设置 → 组件目录”可直接打开） |
| 设置与卡片位置 | `%AppData%\Roaming\WinWidget\config.json` |
| 日志 | `%LocalAppData%\WinWidget\logs\app.log` |

### 城市与定位：`places.js`

内建的天气、一周天气、空气质量、日出日落都用它，你也可以直接用：

```html
<script src="/__fw/places.js"></script>
<script src="main.js"></script>
```

```js
// 需要 "network:geocoding-api.open-meteo.com"，按网络定位还要 "network:get.geojs.io"
const place = await places.locate(widget.settings.get("city"));   // "" → 按 IP 定位
// place: { name: "南昌", lat, lon, tz, at }
// 城市不存在时丢 places.NotFound，message 已经是可以直接显示的一句话

// 把定位结果写回设置，让控制中心的城市框显示目前是哪个城市（用户自己填过就不动）
places.echo(widget, settings, place);
```

结果会存进 `widget.storage`（`geo2:<城市>`、IP 定位是 `geo2:ip`，6 小时后重查一次），所以同一个城市只查一次。

### 事件

| 事件 | 什么时候来 | 内容 |
|---|---|---|
| `ready` | 页面起来了 | `{ visible }` |
| `show` / `hide` | 卡片上屏幕 / 离开屏幕 | `{ from, visible, initial }` |

| `unload` | 卡片被移除或程序结束 | `{ kill }` |

| `state` | 锁定、层级、穿透改变 | `{ locked, layer, clickThrough }` |

uTools 那两个“从外面推东西进来”的事件也能用：

```js
// 别的组件（或控制中心）带着 payload 唤起本组件：redirect("打开链接", text)
utools.onMainPush((action, payload) => {
  // action = { code: "furl", type: "text" | "img" | "files", payload, from: "redirect" }
  openWith(payload);
});

utools.onDbPull(({ direction, docs }) => {
  // direction 永远是 "pull"；docs 是刚变动的文档（删除时不在里面，看 ids 用 db.get 复查）
  refresh(docs);
});
```

## 三个完整例子

### 例 1：把一个网络 API 的数字放上桌面

需求：显示某个 GitHub 专案的 star 数，每 30 分钟更新，断网时显示上次的值。

`widget.json` 重点：`"permissions": ["network:api.github.com"]`。

```js
const $ = (id) => document.getElementById(id);
const KEY = "last";

async function fetchOnce() {
  const r = await widget.fetch("https://api.github.com/repos/Demon1110/WinWidget", {
    headers: { accept: "application/vnd.github+json" },
  });
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  const repo = await r.json();
  return { stars: repo.stargazers_count, at: Date.now() };
}

async function refresh() {
  try {
    const data = await fetchOnce();
    show(data, false);
    await widget.storage.set(KEY, data);
  } catch (e) {
    // 失败时退回上次的值，并在角落标一下“旧数据”
    const old = await widget.storage.get(KEY);
    if (old) show(old, true);
    else $("stars").textContent = "—";
    widget.log(`stars: ${e.message}`);
  }
}

function show(data, stale) {
  $("stars").textContent = data.stars.toLocaleString(widget.locale);
  $("at").textContent = new Date(data.at).toLocaleTimeString(widget.locale, { hour: "2-digit", minute: "2-digit" });
  $("stale").hidden = !stale;
}

refresh();
setInterval(refresh, 30 * 60 * 1000);   // 30 分钟
document.addEventListener("visibilitychange", () => { if (!document.hidden) refresh(); });
```

要点：

- `permissions` 要写 `network:api.github.com`（不是 `*.github.com`：能少就少）。
- 先写画面再写数据，或像上面一样“失败也有东西可显示”，卡片不会一片空白。
- 定时器用 `setInterval` 就好；不要每秒轮询，`widget.media`、`widget.audio` 这类有事件的就用 `onChange`。

### 例 2：每秒更新的系统监控（省电写法）

```js
const $ = (id) => document.getElementById(id);
const bars = [];

// 一次订阅两个主题；WinWidget 会合成一笔数据给你
widget.system.subscribe(["cpu", "memory"], (d) => {
  if (d.cpu) {
    $("cpu").textContent = `${Math.round(d.cpu.usage)}%`;
    push(bars[0], d.cpu.usage);
  }
  if (d.memory) {
    $("mem").textContent = `${Math.round(d.memory.usage)}%`;
    push(bars[1], d.memory.usage);
  }
}, { interval: 1000 });

/** 20 格的迷你曲线；每秒更新，所以不加 transition。 */
function push(bar, value) {
  const cell = document.createElement("i");
  cell.style.height = `${Math.max(4, Math.min(100, value))}%`;
  bar.appendChild(cell);
  if (bar.children.length > 20) bar.firstElementChild.remove();
}
```

```css
#cpu, #mem { font-variant-numeric: tabular-nums; }   /* 数字不会左右跳 */
.mini { display: flex; align-items: flex-end; gap: 1px; height: 1.6rem; }
.mini i { width: 2px; background: var(--w-accent); } /* 不要 transition / animation */
```

要点：

- 每秒更新的元素不要 `transition`、不要 `animation`：一个 0.5 秒的动画等于整张卡片一直在重画，处理器会一直有负担。
- 数字用 `font-variant-numeric: tabular-nums`，宽度不会随数字变动而抖。
- 订阅用完要退订（`const stop = widget.system.subscribe(...); stop()`），否则卡片一直有取样成本。

### 例 3：同一个组件放两个，各记各的

```js
// 卡片自己在拖动和缩放时会变，实例标识不会变：用它当数据分界
const key = `state:${widget.instanceId}`;

const saved = await widget.storage.get(key);
index = saved ? saved.index : 0;

function save() {
  widget.storage.set(key, { index });   // 不用 await，写入很快
}
```

要点：`widget.storage` 的键是**组件**级别的（同一组件的两个实例共用一个文件），要分开保存就在键里带上 `instanceId`；设置值（`settings`）则是每个实例各自一份。

## 写组件的检查列表

交付前逐条看一眼，能省掉九成的“装上去怪怪的”：

1. `widget.json` 的 `id` 只用小写英文、数字和 `. _ -`，2–64 字元，之后不再改。
2. `entry` 指向的文件真的存在；所有资源都用**相对路径**。
3. 文件存成 UTF-8（没有 BOM 也可以，有 BOM 会让 JSON 解析失败）。
4. 用到的能力都在 `permissions` 里声明；能用 `network:某个网站` 就不要 `network:*`。
5. 第一次加载就有东西看：先画版面，再等数据；取不到时给一句人话，不要空白。
6. 每秒更新的元素不加动画；不定时轮询已经有事件的功能。
7. 数字和日期用 `widget.locale` 格式化，文字用 `widget.t()`。
8. 只用 `--w-*` 变数和 `w-*` 样式，三套主题切一遍都不会看不到字。
9. 卡片可以被拉大缩小：用 flex/grid，必要时 `@container`；想让内容跟着放大就设 `grow`。
10. 不要写 `window.open`、页面跳转、`document.write`；要开网页用 `widget.shell.open`。
11. 不要引用 CDN 上的脚本或字体（离线就坏了），要打包进组件文件夹。
12. 送出前在开发者模式按 F12 看一遍 Console，没有红色错误再导出 `.fwz`。

## 常见问题

**改了文件，桌面上没变化。**
确认“设置”里开发者模式是开的。没开的话，在组件上右键 →“重新加载”。如果改的是 `widget.json` 而组件不见了，看“添加组件”页顶部是不是列出了错误。

**`widget.fetch` 失败，说 permission denied。**
把那个网站加进 `permissions`，例如 `"network:api.example.com"`。错误讯息里会写出要加的那一行。如果说 "not allowed yet"，表示已经声明但用户还没允许：到控制中心“我的组件”选这个组件，按“查看并允许”。

**直接用 `fetch()` 或 `<img>` 加载网络上的东西失败。**
网站要在 `permissions` 里。`fetch()` 还要对方支持 CORS；不支持的话改用 `widget.fetch`。

**中文变成乱码。**
把文件存成 UTF-8。

**想让组件第一次出现时大一点或小一点。**
改 `size.width` 和 `size.height`。已经在桌面上的组件会保留用户调过的大小，可以从“添加组件”再放一个新的来看效果。

**怎样让组件在浅色主题（纸本）下也好看？**
文字和线条都用 `--w-*` 变数，不要写死白色或黑色。到控制中心“主题”切换三套主题看一遍。

**改了“语言”设置，组件还是原本的语言。**
语言在**启动时**读 `config.json`，改了要重新启动 WinWidget（控制中心“设置”里的语言会立即影响控制中心本身，桌面上已经开着的组件要重新加载才会换）。组件里请一律用 `widget.locale` / `widget.t()`，不要自己判断系统语言。

**控制中心按“组件目录”“数据位置”没反应，提示“没有成功”。**
这两个按钮由 WinWidget 用系统的方式打开文件夹（等同在资源管理器里双击）。如果完全没反应：先确认路径存在（按钮会自动建立目录），再看 `%LocalAppData%\WinWidget\logs\app.log` 里那一行错误。旧版本把文件夹当成网址开启，所以一定会失败，更新到最新版即可。

**“检查更新”说没有更新通道 / 检查不到。**
`config.json` 的 `update_url` 留空时，默认读本专案 GitHub Releases 的最新版本（`api.github.com`）。要换成自己的通道，就在 `update_url` 填一个 JSON 位址，内容是 `{"version": "1.2.0", "url": "下载位址", "size": 文件大小, "notes": "更新说明", "page": "介绍页"}`。检查和下载都在背景执行，不会让界面卡住；开发者模式不允许自我更新。

**媒体组件里“显示是哪个程序在播放”关掉还有字。**
那是组件页面自己的显示逻辑，最新版已修好。若还留着，确认组件文件夹里的 `style.css` 是最新的（`body.no-app .app { display: none }`）。
